# AnyDash v1 Protocol Contract

## Scope

`protos/anydash/v1/anydash.proto` defines the AnyDash schema in Protobuf package `anydash.v1`. Checked-in `anydash.pb.go`, `anydashv1connect/anydash.connect.go` and `anydash_pb.ts` provide the Go and TypeScript bindings. The server protocol crate (`servers/crates/delino-protos`) and, once implemented, the `cmds/anydash` build script generate Rust from the same schema into their Cargo output directories. This contract fixes every service, method, message, field, enum, error and compatibility rule so that the server, collector, CLI and clients can implement the schema mechanically. It does not establish runtime, native or real-account acceptance. The [project index](project-anydash.md) owns cross-domain invariants; the [server contract](servers-anydash-api-contract.md), [CLI contract](cmds-anydash-cli-contract.md), [provider adapters contract](cmds-anydash-provider-adapters-contract.md) and [application contract](apps-anydash-foundation.md) own behavior behind the interfaces.

## Runtime and Language

Use Protobuf `proto3`, Go package `github.com/delinoio/apps/protos/anydash/v1` (`anydashv1`), Connect-Go package `anydashv1connect` and the TypeScript export `@repo/protos/anydash/v1/anydash_pb`. Clients use `@connectrpc/connect-query` with React Query. Generate server Rust through `servers/crates/delino-protos` and collector Rust through `cmds/anydash/build.rs`; do not check in generated Rust or copy the schema. The file is licensed Apache-2.0 and starts with `// SPDX-License-Identifier: Apache-2.0`. It imports only `google/protobuf/timestamp.proto` and `google/protobuf/duration.proto`. It must pass the repository `buf lint` (STANDARD) and `buf format` checks. Use typed messages and enums; do not add a JSON command API, `google.protobuf.Struct` or `Any` payloads.

## Users and Operators

ReactLynx web, desktop and mobile clients, native widget hosts, the Rust collector and CLI, the Rust `anydash-api` server, and test authors. Operators observe the error and version contracts through server configuration and logs.

## Interfaces and Contracts

### Conventions

- Field numbers: every message table below lists fields in field-number order. Numbers start at 1 and are consecutive, including fields inside a `oneof`, which continue the numbering of the enclosing message. Every enum lists its values after `<ENUM>_UNSPECIFIED = 0` in number order starting at 1; value names carry the upper snake case enum name as prefix (for example `PROVIDER_CODEX`).
- An enum zero value is invalid in requests and stored entities unless a field states that it means "not set". Clients treat unknown enum values received from a newer server as the zero value and render a generic state.
- Identifiers of AnyDash entities (devices, enrollments, connections, dashboards, widgets, activity events, price versions) are lowercase canonical UUID v7 strings generated by the server. `space_id` and user IDs are Delcore tenant IDs and Delcore internal user IDs (also UUID v7). Request IDs (`request_id`) are client-generated UUID v7 values. A malformed identifier returns `INVALID_ARGUMENT` with `field` set.
- Times are `google.protobuf.Timestamp` in UTC. Durations are `google.protobuf.Duration`. An unset message field means "absent", which is different from a zero value.
- Text fields are UTF-8. Display names, dashboard names and widget titles hold 1 to 100 Unicode scalar values after trimming surrounding whitespace, unless stated otherwise, and contain no control characters. `account_label` holds at most 200 scalar values. Model identifiers and metric dimensions hold 1 to 200 bytes of printable ASCII without whitespace. Local paths hold at most 4,096 bytes.
- Decimal amounts are strings matching `^-?(0|[1-9][0-9]*)(\.[0-9]{1,12})?$` in major currency units. `Money.currency_code` is an uppercase ISO 4217 code, or empty when the provider reports an amount without a currency. AnyDash never converts currencies.
- `Page.size` defaults to 50 when zero and allows at most 200. `Page.cursor` is an opaque server cursor bound to the caller, method and filters; a cursor from another context returns `INVALID_ARGUMENT`. `next_cursor` is empty on the last page.
- Creation methods with `request_id` are idempotent for 24 hours per caller and method: an identical replay returns the original result; the same `request_id` with different content returns `REQUEST_ID_REUSED`. Compare decoded request content, not bytes.
- Every list is returned in a stable order defined for its method.

### Transport, credentials and headers

The API serves Connect, gRPC and gRPC-Web at `https://anydash.api.delino.io/anydash.v1.<Service>/<Method>`. `LocalCollectorService` is never served by the API; the collector serves it on local IPC as defined in the [CLI contract](cmds-anydash-cli-contract.md#local-ipc).

Credential kinds:

| Kind          | Presentation                                                                                                               | Holder                                                       |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| User token    | `Authorization: Bearer <Logto JWT>` for the API resource `https://anydash.api.delino.io`                                   | Signed-in web, desktop and mobile clients and native widgets |
| Device token  | `Authorization: Bearer ada_<43 base64url characters>`, the 1-hour device access token                                      | A logged-in collector                                        |
| Refresh token | Request field `refresh_token` holding `adr_<43 base64url characters>`; never a header                                      | A logged-in collector                                        |
| Device code   | Request field `device_code` holding 43 base64url characters; never shown to the user                                       | A collector during enrollment                                |
| Delcore token | Request field `delcore_access_token` holding a Logto JWT for the Delcore API resource; used once per call and never stored | Signed-in clients in `ConnectAccount` and `ListSpaces`       |
| None (local)  | OS-user-restricted local IPC                                                                                               | Desktop app, CLI and desktop native widget hosts             |

Per-service credentials: `DeviceService` methods state their credential below. Every `CollectorService` method requires a device token. `ConnectionService.CreateConnection` and `RegisterConnectionDevice` require a device token; `ListConnections`, `GetConnection`, `UnregisterConnectionDevice` and `RequestConnectionRefresh` accept a user or device token; `DeleteConnection` requires a user token. Every `DashboardService`, `WidgetDataService` and `AccountService` method requires a user token. A method called with the wrong credential kind returns `UNAUTHENTICATED`.

Every request to the API carries `X-AnyDash-Client-Kind` with a `ClientKind` value name (for example `CLIENT_KIND_CLI`) and `X-AnyDash-Client-Version` with a SemVer 2.0.0 version (`MAJOR.MINOR.PATCH` with an optional pre-release). The collector sends `CLIENT_KIND_CLI` and its own executable version, including when the desktop app embeds it. A missing or unparsable header returns `INVALID_ARGUMENT` with `field` set to the header name. Every API response carries `X-AnyDash-Correlation-Id` with a server-generated UUID v7; the server ignores a client-supplied value. Rate-limited responses also carry an HTTP `Retry-After` header in whole seconds, rounded up.

Clients show the guidance from design approval and never retry quota errors automatically.

### Client version compatibility

The server compares `X-AnyDash-Client-Version` with the operator-configured minimum for the `X-AnyDash-Client-Kind` before authentication. An older version returns `UPDATE_REQUIRED` for every API method, including the unauthenticated `DeviceService` methods. A collector that receives `UPDATE_REQUIRED` keeps aggregating and buffers up to 90 days of buckets locally, shows the update notice in `status`, logs and the app, and retries after its next update. `ClientVersionStatus` in `HeartbeatResponse` carries the minimum and latest configured versions for the caller's kind, `update_available` (latest is newer than the caller) and `update_required`.

Enum semantics:

- `ClientKind`: `NATIVE_WIDGET` is a mobile widget extension that calls `WidgetDataService` directly with the app's user token; desktop widget hosts read the local collector instead.
- `CollectorKind`: the client that started the enrollment. One device identity exists per OS user account and machine, shared by the desktop app and the CLI.
- `EnrollmentState`: `PENDING` (code issued), `APPROVED` (user approved, credentials not yet delivered), `CONSUMED` (credentials delivered once), `REJECTED` (user rejected), `EXPIRED` (10 minutes passed), `INVALIDATED` (five failed code attempts).
- `DeviceCredentialState`: `ACTIVE`, `LOGGED_OUT` (the collector revoked its credentials), `EXPIRED` (90 days without an upload), `REUSE_REVOKED` (refresh token reuse detected or the user revoked the credentials). Only `ACTIVE` devices can call `CollectorService`; any state can be reattached by a new enrollment of the same user.
- `ParserState`: `OK`, `PARTIAL` (readable records were aggregated but unreadable records were skipped; the client shows "partial aggregation" and asks the user to update the collector), `NO_SOURCES` (no enabled path exists), `DISABLED` (all paths of the tool are disabled).
- `SpacePermission`: the caller's effective permissions in a space. Personal space: `VIEW_DASHBOARDS`, `EDIT_DASHBOARDS`, `CREATE_DASHBOARDS`, `DELETE_DASHBOARDS`. Team Owner or Admin: all five. Team Member: `VIEW_DASHBOARDS` and `EDIT_DASHBOARDS`. Billing-only users and non-members have no permissions and do not see the space.
- `OnboardingState`: `DEVICE_REQUIRED` while the user has no registered collector device; `READY` otherwise. Team spaces are always `READY`.
- `SharingState`: `PRIVATE` (a personal dashboard widget), `SHARED` (a team dashboard widget whose data owner currently shares its source), `ENDED` (the data owner revoked sharing, left the team, deleted the source or deleted their AnyDash data). `SharingEndReason` gives the cause for `ENDED`.
- `MetricState`: `VALUE` (a value is present), `NOT_PROVIDED` (the provider does not offer the metric; not a failure), `FAILED` (the latest collection failed; readings carry the last successful value and time), `AUTH_EXPIRED` (authentication expired; polling stopped until a valid credential appears or the user reconnects), `PARTIAL` (a value aggregated from incomplete input, such as partial aggregation or a partly computable cost), `CANNOT_BE_CALCULATED` (an estimated cost lacks a price or a required token breakdown). `MetricValue.value` is set only for `VALUE` and `PARTIAL`.
- `MetricTemporality`: `INSTANTANEOUS` values replace each other; `CUMULATIVE` values accumulate over `[period_start, period_end)`. The server never mixes them in one series.
- `MetricKind`: value types are percent for `*_USED_PERCENT`, `*_REMAINING_PERCENT` and `DEPLOYMENT_DISK_UTILIZATION`; duration for `SUBSCRIPTION_WINDOW_DURATION`; time for `SUBSCRIPTION_WINDOW_START` and `SUBSCRIPTION_RESET_AT`; text for `SUBSCRIPTION_PLAN`, `DEPLOYMENT_PLAN`, `DEPLOYMENT_ENTITLEMENT` and `SUBSCRIPTION_PERIOD_KIND` (`weekly` or `monthly`); flag for `SUBSCRIPTION_CREDITS_UNLIMITED` and `SUBSCRIPTION_EXTRA_USAGE_ENABLED`; decimal for `SUBSCRIPTION_CREDITS_BALANCE` and `DEPLOYMENT_USAGE_QUANTITY` (with `unit`); money for the `*_AMOUNT`, `DEPLOYMENT_ON_DEMAND_BUDGET`, `DEPLOYMENT_BILLED_COST` and `DEPLOYMENT_EFFECTIVE_COST` kinds. `SUBSCRIPTION_REMAINING_AMOUNT`, `PLAN_DOCUMENTED_QUOTA` and `DEPLOYMENT_ON_DEMAND_BUDGET` are always `NOT_PROVIDED` in this version. `SUBSCRIPTION_REMAINING_PERCENT` is derived only by the server as `100 − SUBSCRIPTION_USED_PERCENT` for the same connection and dimension and is `NOT_PROVIDED` or `FAILED` when the used percentage is; collectors never report it. The [provider adapters contract](cmds-anydash-provider-adapters-contract.md) maps each provider metric to a kind and dimension.
- `CollectionStatus`: the outcome of one collection cycle. `PARTIALLY_SUCCEEDED` means some metrics or resources failed; `NOT_PROVIDED` means the connection has no data of this category, for example a Codex API-key login.
- `ConnectionState`: derived by the server with precedence `NO_REGISTERED_DEVICE`, `NO_RUNNING_COLLECTOR` (no registered device sent a heartbeat in 5 minutes), `AUTH_EXPIRED`, `ERROR` (latest snapshot `FAILED` or `RATE_LIMITED`), `WAITING_FOR_FIRST_RESULT`, `OK`.
- `ResourceHealth`: the normalized resource status; `provider_status` keeps the provider's raw status value.
- `SnapshotOutcome`: `LATEST_UPDATED` (the observation is newer than the connection's latest observation), `HISTORY_ONLY` (an older, late observation applied only to hourly history), `DUPLICATE` (an observation with the same `observed_at` was already stored for the connection).
- `BucketOutcome`: `APPLIED`, `SAME_VERSION_IGNORED`, `OLDER_VERSION_IGNORED`, `OUTSIDE_RETENTION` (the bucket starts more than 90 days ago), `INVALID` (the bucket starts more than 15 minutes after server time).
- `ActivityKind`: the user-visible activity events defined in the [server contract](servers-anydash-api-contract.md#audit-events-and-user-activity-log).
- `KeySource`, `CollectorRunState`, `LocalNotice` and `SourcePathOrigin`: local collector status values defined in the [CLI contract](cmds-anydash-cli-contract.md).

| `EnrollmentSummary` | `string enrollment_id`, `EnrollmentState state`, `string device_name`, `DevicePlatform platform`, `CpuArchitecture architecture`, `CollectorKind collector_kind`, `string collector_version`, `Timestamp expires_at`, `uint32 remaining_attempts`, `bool reattach` |

Credentials: `StartEnrollment`, `PollEnrollment`, `RefreshDeviceToken` need no bearer token; `PollEnrollment` authenticates with `device_code`, `RefreshDeviceToken` with `refresh_token`. `RevokeDeviceCredentials` accepts the device's `refresh_token` without a bearer token (collector logout) or a user token for any of the user's devices with an empty `refresh_token`. `GetEnrollment`, `ApproveEnrollment`, `RejectEnrollment`, `ListDevices`, `DeleteDevice`, `SetPreferredDevice` and `RequestDeviceSync` require a user token.

Rules:

- `StartEnrollment` creates a `PENDING` enrollment that expires 10 minutes later. `user_code` has 8 characters from `BCDFGHJKLMNPQRSTVWXZ`, displayed as `XXXX-XXXX`; comparison ignores case, whitespace and the hyphen. `verification_url` is `https://anydash.delino.io/connect/<enrollment_id>`; the code is never part of the URL. `poll_interval` is 5 seconds. `previous_device_id` is the locally retained device ID after a logout or credential loss, or empty.
- `GetEnrollment` returns the summary shown on the approval page. `remaining_attempts` starts at 5. `reattach` is true when `previous_device_id` names an existing device of the caller.
- `ApproveEnrollment` requires the `user_code` shown by the collector. A wrong code returns `ENROLLMENT_CODE_MISMATCH` and decrements the remaining attempts; the fifth failure sets `INVALIDATED`, and later calls return `ENROLLMENT_INVALIDATED`. An expired enrollment returns `ENROLLMENT_EXPIRED`; a used one returns `ENROLLMENT_ALREADY_USED`. A correct code reattaches the caller's device named by `previous_device_id`, or creates a new device owned by the caller. A new device beyond 20 returns `QUOTA_EXCEEDED`; a reattach does not count against the quota. Approval does not deliver credentials.
- `RejectEnrollment` sets `REJECTED`; polling then returns `ENROLLMENT_INVALIDATED`.
- `PollEnrollment` returns `PENDING` until approval. The first poll after approval and before `expires_at` returns `CONSUMED` with `device` and `credentials` and is the only response that carries them; later polls return `ENROLLMENT_ALREADY_USED`. An approved enrollment that is not polled before `expires_at` expires, and polls return `ENROLLMENT_EXPIRED` without credentials. Polling faster than `poll_interval` returns `RATE_LIMITED` with scope `ENROLLMENT`. A wrong `device_code` or an unknown enrollment returns `UNAUTHENTICATED` and does not count as a code attempt. A database failure while reading the enrollment is never reported as `UNAUTHENTICATED`, because collectors treat that reason as a permanent invalidation; it returns `INTERNAL` or `DEPENDENCY_UNAVAILABLE` so the collector retries.
- Device access tokens expire 1 hour after issue. `RefreshDeviceToken` rotates the refresh token on every use and returns a new access and refresh token pair; the previous refresh token becomes invalid. Presenting a rotated refresh token again returns `REFRESH_TOKEN_REUSED` and revokes all credentials of the device (`REUSE_REVOKED`). A refresh token expires 90 days after the device's latest accepted upload (`EXPIRED`). The collector stores the new pair durably before using it.
- `RevokeDeviceCredentials` sets `LOGGED_OUT` (refresh token) or `REUSE_REVOKED` (user token) and releases the device's leases. The device registration and its data remain. A later enrollment that names the device reattaches it with new credentials.
- `ListDevices` lists the caller's devices ordered by `enrolled_at`, then `id`.
- `DeleteDevice` blocks the device and its data immediately, revokes its credentials, collection and upload rights, removes it from every connection's candidates, ends its leases and returns the physical deletion deadline (24 hours). External connection history remains with the connection.
- `SetPreferredDevice` sets or clears (empty `device_id`) the user's preferred collection device, which must be one of the caller's devices. A change does not preempt a valid lease.
- `RequestDeviceSync` asks the device to run a local usage sync. It is allowed once per minute per device; an earlier request returns `RATE_LIMITED` with scope `MANUAL_REFRESH` and the remaining wait. The device receives the request through `HeartbeatResponse.local_sync_requested`.

### CollectorService

Device-token operations of a running collector.

| Method               | Request fields in field-number order from 1                                             | Response fields in field-number order from 1                                                                                                                           |

| `Heartbeat`          | `string collector_version`, `string os_version`, `repeated string ready_connection_ids` | `Timestamp server_time`, `ClientVersionStatus version_status`, `repeated ConnectionAssignment assignments`, `bool local_sync_requested`, `Duration heartbeat_interval` |
| `UploadUsage`        | `repeated UsageBucket buckets`                                                          | `repeated BucketResult results`, `Timestamp retention_start`                                                                                                           |
| `ReportParserStatus` | `repeated ParserStatus statuses`                                                        | none                                                                                                                                                                   |
| `AcquireLease`       | `string connection_id`                                                                  | `bool granted`, `Lease lease`                                                                                                                                          |
| `RenewLease`         | `string connection_id`, `uint64 epoch`                                                  | `Lease lease`, `bool refresh_requested`                                                                                                                                |
| `ReleaseLease`       | `string connection_id`, `uint64 epoch`                                                  | none                                                                                                                                                                   |
| `ReportSnapshot`     | `string connection_id`, `uint64 lease_epoch`, `Snapshot snapshot`                       | `SnapshotOutcome outcome`                                                                                                                                              |

| Message                | Fields in field-number order from 1                                                                                        |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `ConnectionAssignment` | `string connection_id`, `Provider provider`, `Lease lease`, `bool acquire_recommended`, `bool refresh_requested`           |
| `UsageBucket`          | `LocalTool tool`, `string model`, `Timestamp bucket_start`, `uint64 version`, `uint64 session_count`, `TokenCounts tokens` |
| `BucketKey`            | `LocalTool tool`, `string model`, `Timestamp bucket_start`                                                                 |
| `BucketResult`         | `BucketKey key`, `BucketOutcome outcome`, `uint64 stored_version`                                                          |

Rules:

- `Heartbeat` is sent every minute (`heartbeat_interval` is 60 seconds). It records `last_heartbeat_at`, the collector and OS versions and the connections in `ready_connection_ids` (IDs of connections the device is not registered for are ignored). It extends every valid lease the device holds to 5 minutes after the heartbeat. `assignments` holds one entry per connection the device is registered for, ordered by connection ID. `acquire_recommended` is true when no valid lease exists and the device is the selected candidate; `refresh_requested` is true once after a manual refresh request for a connection whose lease the device holds. `local_sync_requested` is true once after `RequestDeviceSync`.
- Candidate selection for a connection without a valid lease considers registered devices that are online, `ACTIVE` and ready for the connection: the user's preferred device first, otherwise the device with the most recent heartbeat, with ties broken by the lower device ID.
- `AcquireLease` grants a new lease only when no valid lease exists and the caller is the selected candidate. Every grant increments the connection's epoch by one; epochs start at 1 and are never reused, including after devices or leases change. If the caller already holds the valid lease, the response returns `granted=true` with the unchanged lease. Otherwise it returns `granted=false` with the current valid lease, or no lease.
- `RenewLease` extends the caller's valid lease when `epoch` equals the current epoch; otherwise it returns `LEASE_EXPIRED`. `refresh_requested` has the heartbeat meaning.
- `ReleaseLease` ends the caller's lease immediately when `epoch` matches; otherwise it succeeds without change.
- `ReportSnapshot` is accepted only when `lease_epoch` is the current epoch, the caller holds the lease and the lease is valid at receipt; otherwise it returns `LEASE_EXPIRED`, including for a device that comes back after losing its lease. `snapshot.observed_at` must not be earlier than the lease's `acquired_at` or later than receipt plus 60 seconds (`INVALID_ARGUMENT`). Collectors never report `SUBSCRIPTION_REMAINING_PERCENT`.
- `UploadUsage` accepts at most 2,000 buckets and 1 MiB per request (`PAYLOAD_TOO_LARGE` otherwise); the initial 90-day backfill is split into chunks. The whole request returns `INVALID_ARGUMENT` for an unspecified tool, an empty or invalid model, a `bucket_start` that is not aligned to a 15-minute UTC boundary or lies outside years 1 to 9999 UTC, a zero version or a duplicated bucket key. Otherwise each bucket gets one `BucketResult` in request order. `version` increases whenever the bucket's cumulative values change; collectors derive it from the microsecond UTC time of the aggregation that produced the value, forced to be strictly greater than the previous version of the same bucket. A higher version replaces the stored bucket (`APPLIED`); an equal version is ignored (`SAME_VERSION_IGNORED`), even if its content differs; a lower version is ignored (`OLDER_VERSION_IGNORED`). `session_count` counts sessions that start in the bucket; tokens count usage that occurs in the bucket. `retention_start` is the oldest bucket start that the server accepts now.
- `ReportParserStatus` replaces the device's latest status per tool. An absent `observed_at` is stored as absent; a present `observed_at` outside years 1 to 9999 UTC returns `INVALID_ARGUMENT` for `statuses[i].observed_at`.
- Accepted `UploadUsage` and `ReportSnapshot` calls count as uploads for the 90-day refresh token expiry.

Rules:

- Both methods require `VIEW_DASHBOARDS` and apply the onboarding and space-state rules. `QueryDashboardData` returns one `WidgetData` per widget in dashboard order.
- `time_zone` is an IANA name; empty uses the account setting. An unknown name returns `INVALID_ARGUMENT`.
- Periods in the selected time zone: `LAST_24_HOURS` is the 24 hours before now; `TODAY`, `THIS_WEEK` (ISO week starting Monday) and `THIS_MONTH` start at local midnight of the first day; `LAST_7_DAYS`, `LAST_30_DAYS` and `LAST_90_DAYS` are that many local calendar days including today. Ranges end now and never start earlier than the 90-day retention.
- Local usage hourly and daily points cover local hours and days built from 15-minute UTC buckets, so 30- and 45-minute offsets stay exact. Across DST changes a day has 23 or 25 hours; a repeated local hour appears twice with different `utc_offset_minutes`, and a skipped hour has no point.
- Metric history `HOUR` points are the stored hourly UTC snapshots (the last successful value in each UTC hour). `DAY` points are the last successful hourly snapshot in each local day. Instantaneous and cumulative series are separate.
- `MetricReading.current` is the latest state. When it is `FAILED` or `AUTH_EXPIRED`, `last_success` and `last_success_at` carry the last successful value and time, and `failure_class` the cause.
- `CostEstimate`: each bucket is either computable (every required token count and price exists in the price version in effect at the bucket time) or not. Totals are `VALUE` when all contributing buckets are computable, `CANNOT_BE_CALCULATED` when none are, and `PARTIAL` with the sum of computable buckets otherwise. `amount_usd` is a decimal USD string rounded half up to 6 decimal places; `price_version_ids` lists the distinct versions used. Estimated costs are labeled separately from subscription fees and actual bills.
- `notices`: `POSSIBLE_CROSS_DEVICE_DUPLICATION` on local usage data from two or more devices; `PARTIAL_AGGREGATION` when an included device and tool reports `PARTIAL`; `NO_RUNNING_COLLECTOR` when an included connection or device has no heartbeat in 5 minutes; `ESTIMATED_COST` whenever an estimated cost is present; `BACKFILL_LIMITED` when the range starts before the earliest stored bucket of an included device enrolled less than 90 days ago.
- `UsageBreakdownRow.parser_state` and `skipped_record_count` summarize the parser statuses of the devices and tools behind the row: a `DEVICE` row covers the tools of that device, a `TOOL` row covers that tool on every included device, and a row with neither (`MODEL` breakdown) reports `PARSER_STATE_UNSPECIFIED` and zero. The state with the highest precedence wins, `PARTIAL` > `OK` > `NO_SOURCES` > `DISABLED`, so the same stored data always yields the same state in `QueryWidgetData` and `QueryDashboardData`. `skipped_record_count` is the sum over all covered statuses.
- `sharing_state` `ENDED` returns no `summary` and no `content`. Clients and native widgets delete cached data for that widget and show "sharing ended".
- `WidgetSummary` is the compact form for native widgets: English labels and up to two values chosen by the server from the widget content, plus `data_updated_at`, the observation time of the newest included value.

Rules:

- `GetCollectorStatus` returns the fields that `anydash status` prints, including the device ID, connection IDs, collector version, parser states, the correlation ID, reason and time of the last error and update notices.
- `StartLogin` starts enrollment and returns the user code and URL; `ALREADY_LOGGED_IN` when active credentials exist. The collector polls and stores the credentials itself; `CollectorStatus.login` reports progress.
- `Logout` revokes and deletes the local device credentials, releases leases and stops collection and upload. The device ID, local buffer and provider credentials remain for reattachment.
- `AddConnectionCredential` validates the credential with one read-only provider request (or checks that the local CLI credential is readable), stores the secret encrypted, then calls `CreateConnection` or `RegisterConnectionDevice`. Secrets never leave the device.
- `RemoveConnectionCredential` deletes the local secret, releases the lease and unregisters the device from the connection.
- `ListSourcePaths`, `AddSourcePath`, `DisableSourcePath` and `EnableSourcePath` manage detected and user-added session paths.
- `RotateKey` decrypts and re-encrypts all secrets with a new key in one atomic step; failure returns `KEY_ROTATION_FAILED` with the old key and ciphertext in place.
- `RequestLocalSync` runs a local sync now; allowed once per minute (`RATE_LIMITED` with the remaining wait).
- `RequestLocalConnectionRefresh` makes the collector call `ConnectionService.RequestConnectionRefresh` for `connection_id` with its own device token and returns the server's `next_allowed_at`. Local clients never present the device credentials themselves while a collector runs. A malformed `connection_id` returns `INVALID_ARGUMENT` with `field` `connection_id` before any API call, and a collector without active device credentials returns `NOT_LOGGED_IN`. API errors from the call or from a device token refresh, such as `RATE_LIMITED` with scope `MANUAL_REFRESH`, `NOT_FOUND`, `UPDATE_REQUIRED`, `DEVICE_CREDENTIALS_INACTIVE` and `DEPENDENCY_UNAVAILABLE`, are returned with the API's `ErrorDetail` unchanged, including its correlation ID; a network failure returns `DEPENDENCY_UNAVAILABLE` with a local correlation ID.
- `PutNativeWidgetSnapshots` stores up to 100 snapshots written by the desktop app; `replace_all` replaces the stored set. `ListNativeWidgetSnapshots` returns them to desktop widget hosts. An `ENDED` snapshot has no summary; hosts delete displayed data and show "sharing ended".
- `Quit` stops the collector; `SERVICE_MANAGED` when the installed user service owns the process.

### Buf compatibility rules

- The repository `buf.yaml` FILE breaking rules apply to `protos/anydash/v1` from the first merged version. Run `node protos/scripts/check-breaking.mjs <base>` for schema changes.
- Never renumber, rename, remove or change the type of a field, enum value, message, service or method, and never move a field into or out of a `oneof`. Mark obsolete fields `deprecated` and stop using them; reserve the numbers and names of anything removed.
- Add fields with new numbers and give their zero value the meaning "absent" or "unknown". Add enum values only at the end; older clients treat unknown values as the zero value.
- New request fields must be optional for the server so that older clients keep working; the server stays backward compatible with every client at or above the configured minimum version.
- `LocalCollectorService` follows the same rules because the desktop app, the CLI and the embedded collector can have different versions on one device.

## Storage

The schema defines wire formats only. The [server contract](servers-anydash-api-contract.md#storage) owns PostgreSQL tables and the [CLI contract](cmds-anydash-cli-contract.md#storage) owns the local store. Stored enum values use the numeric values above.

## Security

Resolve users, devices and spaces from validated credentials, never from request ownership fields. Bind cursors, request IDs and leases to the authenticated user or device. External provider secrets appear only in `LocalCollectorService.AddConnectionCredential`, which never leaves the device. Device and refresh tokens and device codes are bearer secrets: never log them. Responses never include another user's connection or device details, only shared widget display data.

## Logging

Log the method, correlation ID, result category, `ErrorReason`, client kind and version and duration. Never log tokens, device codes, user codes, provider secrets, prompts, response bodies, local paths or model-level usage values.

## Build and Test

At schema implementation run root `pnpm proto:lint`, `pnpm proto:generate` followed by a clean `git status` for `protos`, `go vet ./protos/...`, `go test ./protos/...`, `cargo build --locked --manifest-path servers/Cargo.toml -p delino-protocol` and the breaking check against the base revision for later changes. Consumers test error mapping, version headers and idempotency through their own contracts. Schema generation does not establish runtime acceptance.

## Dependencies and Integrations

Repository protocol generation (`buf.gen.yaml`), `@repo/protos`, `servers/crates/delino-protos` and the `cmds/anydash` build script. The [Delcore protocol](protos-delcore-v1-contract.md) remains service-neutral and owns identity, tenant and role messages; AnyDash refers to Delcore IDs only.

## Change Triggers

Change the server, CLI, provider adapters and application contracts together when wire fields, enum meaning, error mapping, limits or compatibility rules change. Update the project index when services or hosts change. Update scoped instructions only for ownership or development-rule changes; follow the [instruction-update policy](README.md#instruction-update-policy).
