# Repository workflow contract

Install with `pnpm install --frozen-lockfile`. Run `pnpm test` in each app, root `cargo test`, and `go test ./...`. Generate frontend `dist` before Rust validation, then remove generated `dist` directories. Native builds, device launches, account-backed integration and store acceptance are separate checks. Preserve source revision, commands, results and unperformed checks in commits and CI artifacts.

CI compares PRs with their base, pushes with the previous revision, and manual runs with the main merge base (or the parent on main). Manual validation remains affected-only. Ordinary CI runs on Ubuntu; macOS is restricted to the separate main-only mobile release workflow. Protocol validation includes Go format, vet, unit tests and consumer example build. Real PostgreSQL integration and OCI checks belong to servers. Protocol changes require lint, format, regeneration freshness and FILE breaking checks against the comparison revision.

Mobile dispatch preserves signed build-only mode and opt-in Google Play internal/TestFlight uploads. Configure the protected environment described in the application contract before use. Release workflows do not establish store acceptance until run with real accounts.

The Tauri wrapper consumes the immutable release and hashes in `prebuilt-dependencies.lock.json`. These shared binaries remain published by `delinoio/oss`; keep that producer URL and source pin unchanged. Local source builds are explicit; CI source fallback is forbidden.

Use root `pnpm format` and `pnpm format:check` for changed supported files. Lefthook formats staged files while preserving unstaged changes. CI passes the exact comparison through `TURBO_SCM_BASE` and `TURBO_SCM_HEAD`. Track assets of at least 512 KiB with exact-path Git LFS entries and hydrate them before builds. Schema-only baseline checks skip unrelated LFS smudging.

Older baselines use the former Go module path or the separate generated-code directory. Breaking validation normalizes only the exact historical `go_package` options to the `github.com/delinoio/apps` colocated package path, preserving all wire and remaining FILE checks. Remove this compatibility projection when all supported baselines use the colocated package path.

CI retains separate `devbase-frontend`, `delino-site-frontend`, `delidev-frontend`, `delitools-frontend`, `rust-checks`, and `protocol` jobs. The planner gates each project job before runner allocation. `validate` checks formatting, tooling fixtures, and workflow syntax. `ci-result` fails if any selected job fails, is canceled, or is skipped. Unselected project jobs must remain skipped.

Rust validation installs the Linux native dependencies, generates only the selected shells' frontend output, runs all-target tests and all-target/all-feature Clippy with warnings denied, and checks Rust formatting. Cache restores are available to PRs; pnpm and Cargo caches are saved only after successful main validation. Each validation job retains a JSON artifact with the source revision, comparison, commands, outcomes, and unperformed native/account checks. Protocol freshness rejects both tracked and untracked generated changes.

Server runtime validation belongs to the private `delinoio/servers` repository. External contributors can submit apps changes with the applicable apps checks and must report server integration as unperformed if they cannot run it. Maintainers with servers access own private contract updates and server validation before adopting a protocol revision. Public reviews must contain only safe interface effects and validation outcomes; private evidence stays in servers. See the [repository boundary contract](repository-boundary-contract.md) for the contribution boundary and the maintainer adoption procedure.
