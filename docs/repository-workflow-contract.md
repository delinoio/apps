# Repository Workflow Contract

## Scope

The repository contains shared instructions, skills, documentation templates, formatting infrastructure, two static Rspress sites ([`delino-site`](project-delino-site.md) and [`delino-docs`](project-delino-docs.md)) and the [`delino-accounts`](project-delino-accounts.md) project with an Rsbuild web app and a Go API server. It has no native build workspace, generated protocol bindings, deployment workflows or release credentials.

## Agent skills

`.agents/skills/` owns the shared workspace-local agent skills. `.claude/skills` is a tracked relative symlink to `../.agents/skills` so that Claude Code discovers the same skills as Codex. Add, edit and remove skills only in `.agents/skills/`; do not replace the symlink with a copy or add Claude-only skill directories. Checkouts on platforms without symlink support (for example, Windows without `core.symlinks`) get a plain file instead and do not expose the skills to Claude Code.

## Installation

Use Node.js 24 from `.nvmrc` and pnpm 10.26.2 from `package.json`. The Go toolchain selected by the root `go.mod` (Go 1.26.1 or later) is also a prerequisite for the root `pnpm build`, `pnpm dev`, `pnpm lint` and `pnpm test` tasks, because they include `servers/accounts-api`, whose package scripts call `go`. All Go code belongs to the single root module `github.com/delinoio/mono`; nested `go.mod` and `go.work` files are not used. Run `pnpm install --frozen-lockfile`. The prepare script installs Lefthook through `scripts/install-git-hooks.sh`. Archives without Git metadata skip hook installation, including archives extracted inside another Git work tree, because the installer runs only when the project directory is the root of its own work tree. Linked worktrees may use their shared Git hooks directory; unrelated custom hook paths remain protected.

## Task orchestration

The pinned `turbo` dependency and root `turbo.json` orchestrate packages selected by `pnpm-workspace.yaml`: `apps/*`, `packages/*` and `servers/*`. The workspace packages are `apps/delino-site`, `apps/delino-docs`, `apps/delino-accounts` and `servers/accounts-api`; commands only run tasks that exist in package scripts. Go server packages wrap the Go toolchain in their package scripts and disable Turbo caching for their tasks because the toolchain and module cache are not declared inputs.

Root `pnpm build`, `pnpm dev`, `pnpm lint`, `pnpm typecheck` and `pnpm test:e2e` delegate to `turbo run`. The `test:e2e` task runs app end-to-end suites, is uncached and declares its pass-through environment according to the [e2e contract](repository-e2e-contract.md). Root `pnpm test` runs workspace tests and the repository-wide `test:tooling` task. The latter runs the existing formatter and hook fixtures directly and is registered as `//#test:tooling`. It is uncached so each invocation checks the current Git and hook environment. `prepare`, `format` and `format:check` remain direct commands: hook installation has side effects, and formatting depends on Git revisions, staged changes and untracked files rather than package inputs.

Root `pnpm dev` starts all workspace development servers together through the unfiltered `turbo run dev` command. Each workspace package that owns a development server exposes it through its `dev` script. Packages without a development server do not need a `dev` script. Package-specific development is available through an explicit filtered command; the root command always selects all packages. It currently starts the Rspress development servers of `delino-site` and `delino-docs`, the Rsbuild development server of `delino-accounts` and the `accounts-api` Go server.

Define each workspace task in its owning `package.json`. Declare workspace dependencies so Turbo can order tasks: builds depend on dependency builds, tests depend on dependency builds, and lint and typecheck tasks depend on their corresponding dependency tasks. Build output defaults to `dist/**`; packages with other outputs must override them in a package-local `turbo.json` that extends `//`. Declare any additional test reports or incremental compiler outputs there. Development tasks are persistent and uncached.

Turbo uses strict environment mode by default. Package contracts and package-local task configuration must declare environment variables, ignored configuration inputs and shared root inputs that affect results before enabling their caching. Keep side-effecting or environment-dependent tasks uncached when their inputs cannot be fully declared. Do not route Git-sensitive formatting through cached tasks or pass credentials through global environment wildcards. Development tasks pass the configuration variables that their owning package contract defines through task-level `passThroughEnv` in that package's `turbo.json`, so root `pnpm dev` honors shell-provided values like the package-specific commands. Use `passThroughEnv`, not `env`, so the values stay out of the hashes of these uncached tasks, and list only variables of the package that owns the task. Add a variable that a development server reads to the owning package's `turbo.json` in the same change. The `scripts/ci/turbo-env.test.mjs` fixture checks the resolved `dev` task definitions with a Turbo dry run. Remote caching is not configured. `.turbo/` is ignored local state; generated `dist` directories remain subject to the cleanup rule below.

For a package subset, use `pnpm exec turbo run <task> --filter=<package>`. Use `pnpm exec turbo run <task> --dry=json` to inspect the graph without running tasks. Root-only fixture execution is also available as `pnpm test:tooling`. New runtime projects must add their own contracts and package scripts before these commands can establish runtime acceptance.

## Formatting

Root `pnpm format` writes fixes and `pnpm format:check` checks without rewriting. Both use pinned Rstack and `rstack.config.ts`. Default local selection compares the merge base of `origin/main` and HEAD, including working changes and untracked files. Explicit `--base <sha> --head <sha>` arguments select that committed comparison. Local `--all` selects existing tracked files. Before the first commit, use `--staged`.

Lefthook runs `node scripts/ci/format-changed.mjs --staged --write` with `stage_fixed: true`. It preserves unstaged edits, supports initial commits and rejects parser failures. Select files with NUL-separated Git paths, skip deletions and symlinks, and preserve imported skills, generated files and lockfiles through shared exclusions.

CI requires an explicit comparison and rejects local `--staged` and `--all` modes. An unset, empty or case-insensitive `false` CI value means local execution; every other nonempty value enables CI restrictions.

## Validation

Run `pnpm test` for formatter, hook and change-planning fixtures. CI plans affected fixtures and formatting on Ubuntu for pull requests, main pushes and manual dispatch. The `quality` job runs plain `pnpm format:check` with `TURBO_SCM_BASE` and `TURBO_SCM_HEAD` set to the resolved comparison; the formatter reads that environment as the explicit comparison. The `--base <sha> --head <sha>` arguments are the equivalent local form and select the same files. PR comparisons use the pull request base and head. Push comparisons use the prior and current commits. Manual comparisons use the merge base with `origin/main`; an optional `base` input selects another existing revision. A root push has no previous commit, so CI creates a local empty-tree comparison commit without pushing it. No full manual mode or macOS runners are configured.

The `changes` job resolves that comparison and runs `scripts/ci/plan.mjs` without installing dependencies. It publishes `base`, `head`, `format`, `fixtures`, `quality`, `go` and `e2e` outputs. Formatting uses the existing formatter's changed-file selection; Rstack still owns exclusions. Fixtures run for changes, deletions or renames affecting `scripts/ci/`, `scripts/install-git-hooks.sh`, `.github/workflows/CI.yml`, `.nvmrc`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `rstack.config.ts`, `lefthook.yml`, any `turbo.json` (the root file or a workspace package file) or the `package.json` placed directly inside a workspace package under `apps/`, `packages/` or `servers/`. Adding, removing or renaming a workspace package changes the packages that the Turbo fixtures resolve, so a nested `package.json` deeper in a package does not select fixtures. Documentation-only changes select formatting without fixtures. The `quality` job runs when either check is selected and passes the exact comparison to formatting. Empty comparisons or changes with no validation inputs skip `quality`. The `go` output is selected when a changed, deleted or renamed path is a `.go` file, `go.mod` or `go.sum`, and for every `push` event to `refs/heads/main` regardless of the comparison. Branch-wide cancellation can cancel a main-push run before its Go job finishes, and the next push compares only against its own parent, so the planner reads the runner-provided `GITHUB_EVENT_NAME` and `GITHUB_REF` and runs the Go checks against each main-push head; a later documentation-only push therefore cannot pass `ci-result` with Go skipped. Pull request and manual comparisons keep affected selection, and the other outputs are unchanged. The planner logs the reason in the `goReason` field (`diff` or `main-push`) of its record without publishing it as an output. The `go` job then runs `gofmt -l` on tracked `.go` files and `go vet ./...` and `go test ./...` in the root Go module, and records the result in the job summary. The `e2e` output is selected when a changed, deleted or renamed path is inside an `apps/<app>/` package, or is `.github/workflows/CI.yml`, `.nvmrc`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` or `turbo.json`. The `e2e` job installs Chromium and runs every app suite with `pnpm test:e2e`, as the [e2e contract](repository-e2e-contract.md#ci) describes. It reads the `AI_GATEWAY_API_KEY` repository secret and excludes tests tagged `agent` when the secret is not available. The planner records the checkout revision, comparison and selections in logs and the job summary. New shared validation dependencies must update the planner inputs.

Each CI run records the validation revision, comparison revisions, commands and results in its logs and job summary. Runtime and platform acceptance must be added with the owning project. CI runs the e2e suites of `delino-site`, `delino-docs` and `delino-accounts` against their development servers. CI does not build or deploy these apps yet, and it does not run the `delino-accounts` unit tests. Passing shared fixtures does not establish runtime or release acceptance.

The `ci-result` job aggregates validation through `needs`, including `changes`, `quality`, `go` and `e2e`. It runs with `always()` so dependency failures do not skip the aggregate check. Failed or cancelled dependencies fail `ci-result`. The `changes` job must succeed; a skipped `quality`, `go` or `e2e` job passes only when the planner did not select it. Successful dependencies and other skipped dependencies pass. Every new PR validation job must be included in `ci-result.needs`. The aggregate job runs on Ubuntu for the same PR, main-push and manual-dispatch events.

## Assets and licensing

Every repository-owned `dist` directory is ignored generated output and must be removed after validation. Assets at least 512 KiB require exact-path Git LFS attributes and hydration before use. There are no LFS assets yet.

## Dependency updates

Renovate extends `github>delinoio/renovate-config`. Ordinary updates and lockfile maintenance use Monday 00:00–04:00 in `Asia/Seoul`; vulnerability updates retain the inherited immediate security policy. Follow the dependency security contract and retain unresolved findings in pull requests, Linear issues or CI records.
