# Delino localization contract

## Ownership

`delino-site`, `delino-docs` and `delino-console` use English (`en`) as their source language and publish these target languages, identified by BCP 47 tags: Korean (`ko`), Japanese (`ja`), Simplified Chinese (`zh-Hans`), Spanish (`es`), French (`fr`), German (`de`) and Brazilian Portuguese (`pt-BR`). All three apps register the same set. Right-to-left languages are not registered until the layouts define mirroring. Each app owns its `i18n/locales.json` language registry and `i18n/messages/<language>.json` flat text catalog. Documentation sources live under `apps/delino-docs/docs/en`; translated pages use sibling language directories. Shared tooling lives in `scripts/localization/`.

English routes keep their existing paths. Other languages use `/<language>/`, for example `/ja/` and `/zh-Hans/`. Language selection is explicit and links between Delino Site and Delino Docs retain the selected language. Rspress owns documentation language selection, navigation, search and HTML language metadata. The marketing and console apps emit one HTML entry per registered language and load only their selected text catalog.

## Translation workflow

Run these commands from the repository root or an owning app. At the root, `pnpm i18n:translate` and `pnpm i18n:check` run the corresponding command in every workspace that provides it, currently Delino Site, Delino Docs, Delino Console, Labs Site and Labs Docs. Future apps participate by providing these package scripts. Workspaces without localization scripts are skipped. Generation runs up to two workspaces concurrently. Each workspace runs up to two translation requests concurrently, for at most four in-flight translation requests per root invocation. A failed request group prevents later groups in that app from starting. Successful batches in that group are saved before the app fails. The root command fails if any workspace fails. Account commands use the same shared local session from either location.

- `pnpm i18n:login`: continue with ChatGPT in the system browser and authorize ChatGPT plan usage.
- `pnpm i18n:models`: list models available to the connected account.
- `pnpm i18n:translate`: generate missing or source-changed translations. Set `DELINO_TRANSLATION_MODEL` to a model slug from the account catalog; otherwise use the first listed model.
- `pnpm i18n:check`: validate catalog keys, document coverage, protected syntax and source fingerprints without network access or credentials.
- `pnpm i18n:logout`: end the renewable session and clear local credentials while retaining the host and registration identifiers.

`pnpm i18n:translate ko` restricts generation to one target language, including when run for all apps from the root. `pnpm i18n:profiles` lists saved registrations; `pnpm i18n:login <profile-id>` reauthorizes and selects one, and `pnpm i18n:login --new` adds a separate registration. A fresh host UUID is an opaque OAuth installation identifier, not a persisted business entity.

To add a language, add its BCP 47 `lang` and native `label` to each app's registry, run root `pnpm i18n:translate`, review the generated files, and run each app's `pnpm test`. The registry drives routes and language menus; adding a language must not require switch statements in runtime code. Keep English text in catalogs rather than components. Keep product names unchanged in translations.

The generator treats catalog values and Markdown pages as translation units. It batches up to 40 catalog values or one Markdown page per request, and saves completed batches so reruns resume remaining work. Within each app, output and state writes run sequentially after each request group finishes. A per-app lock in the OS temporary directory rejects overlapping generation commands for the same checkout; the error identifies the lock to remove after confirming an interrupted process has stopped. It records SHA-256 source fingerprints in each app's `i18n/state.json`. It preserves unchanged human-reviewed translations. Changed units are replaced only by an explicit translation command. New source text, missing output, obsolete units and invalid translations fail the offline check. Remove obsolete catalog keys/pages and their state entries explicitly when removing source content. Review translations for meaning; structural validation cannot establish linguistic accuracy. Source MDX fails validation until an explicit contract defines how to protect its executable content.

Documentation `theme.*` catalog entries originate from the pinned Rspress theme and retain its MIT license. Preserve `apps/delino-docs/i18n/NOTICE` and `RSPRESS-LICENSE` in source and generated distributions. Other repository-owned catalogs and tooling use Apache-2.0.

Code spans, fenced code, placeholders, Markdown link destinations and non-text frontmatter fields must be preserved during translation. Internal absolute document links are localized by the tool after translation. Public content stays limited to the curated documentation app; the generator must not read internal repository contracts as translation input.

## English-only documentation coverage

Translated coverage remains the default for every discovered source page and catalog key. An app can declare `sourceOnly` in `i18n/locales.json` when its owning product contract requires English-only content. The source language must be `en`. `pages` lists exact Markdown paths relative to `docs/en/`; `messages` lists exact source catalog keys. Do not use directory prefixes or globs. Discovery still reads every source page, rejects MDX and symbolic links, and validates nonempty content. Unknown, duplicate or removed declarations fail. An undeclared new page or key requires translations, including one added below an English-only service directory. Translated output or state for a declared English-only unit fails as obsolete; the tool does not delete it.

Perfine declares its nine public pages and Lane declares its five public pages, each with its dedicated navigation keys, as English-only. Shared navigation text, including the troubleshooting label, remains translated. Service navigation uses this same page registry and omits Perfine and Lane in other languages. On an English-only page, the desktop and mobile language menus open the selected language's service directory. They do not label that destination as an alternate translation. Other pages retain same-page language switching.

A shared directory page can contain an explicitly registered English-only section. `sourceOnly.sections` maps its exact source path to a list of section IDs. Delimit each section with standalone `<!-- i18n:source-only <id> -->` and `<!-- i18n:end -->` lines. The English page renders the section content normally. Only the text outside those delimiters is translation input and the source of its translation fingerprint. The section, its marker lines and one optional following blank separator line are removed, without other whitespace normalization, before the existing fingerprint normalization. Thus adding the Perfine directory entry does not invalidate translations of unchanged shared content. Changes outside the section still fail freshness validation. Missing, duplicate, nested, empty or undeclared sections fail. This mechanism is limited to content covered by an explicit English-only product requirement; do not wrap shared prose to bypass translation freshness.

English-only units need no translation fingerprints because they have no translated output. All translated units retain SHA-256 tracking, protected syntax checks and explicit regeneration. Internal absolute links to English-only pages remain unprefixed during translation, including query strings and fragments. Code examples remain literal. Apps opting into mixed coverage validate absolute document links in source and translated Markdown, reference definitions and frontmatter against the discovered route set; localized routes for English-only pages do not exist. Duplicate source routes fail. These checks validate route existence, not fragment targets or external URLs. Production-build tests also verify rendered route and navigation links.

## ChatGPT authentication and inference

Translation is a local maintainer operation. The localization integration does not authenticate visitors or invoke AI from the browser. The CLI follows [Sign in with ChatGPT](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt) and the official [registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [session](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) and [inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) contracts. It requires an eligible ChatGPT plan and the granted `chatgpt.tokens.use.direct` permission; identity sign-in alone is insufficient.

The CLI generates a stable installation host ID, uses dynamic client registration, PKCE, random state and nonce, and binds its callback listener to `127.0.0.1`. It verifies ID-token signature, issuer, audience, expiration and nonce with `jose`. Account registrations remain separate, and returning sign-in reuses the issued client ID. Tokens are stored atomically with owner-only permissions outside the checkout under `~/.config/delino-translations/`. Serialize local auth operations to avoid rotating-refresh-token races. Translation requests acquire the auth lock only to reload the latest session and refresh tokens if needed, then release it before inference. Contending token requests wait up to 30 seconds for the lock; other account operations report a lock conflict immediately. Login, logout and profile operations retain their exclusive auth lock. Inference does not retain credentials in a long-lived client snapshot. Do not read Codex credentials or put tokens in source, browser bundles, logs or CI artifacts.

Discover account-specific models through the public models endpoint. Inference uses the public Responses API with `store: false` and `stream: true`. Accept output only after `response.completed`; fail on refusals, incomplete responses, usage limits or interrupted streams without recording the unit as translated. Show that generation uses the ChatGPT plan and provide `https://chatgpt.com/settings/usage` for managing usage. No API key, copied OAuth token or hosted translation service is required.

## Validation

Each app's `pnpm test` runs offline localization validation, TypeScript checks and a production build. Shared tooling tests use mocked authentication and inference; real sign-in, consent, account model discovery and completed plan-backed inference require separate account acceptance. Local builds do not establish Cloudflare deployment acceptance. Keep source revision, commands, results and unperformed account/platform checks in commits or CI records.
