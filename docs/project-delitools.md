# Project: DeliTools

## Goal

Provide useful end-user tools through desktop, mobile and web applications, with usage-based billing through delcore. Retain the desktop, Android and iOS hosts and the mobile distribution pipeline.

## Project ID

`delitools`. The npm workspace is `delitools`; the native package is `delitools-shell`.

## Domain Ownership Map

- `apps/delitools`: shared React frontend for the web application at `https://delitools.delino.io`, CEF desktop host and Wry mobile host.
- `.github/workflows/release-delitools.yml`: tagged Cloudflare Pages web publication. Shared version preparation follows the [workflow contract](repository-workflow-contract.md#project-release-preparation).
- `apps/delitools/scripts/mobile-workflow.test.mjs`: fixture checks for the mobile release workflow.
- `.github/workflows/release-delitools-mobile.yml`: signed Android internal testing and iOS TestFlight uploads.
- `servers/delitools-api`: independent Rust public Connect API, PostgreSQL migrations and OCI packaging under FSL-1.1-ALv2.
- `protos/delitools/v1`: schemas and checked-in generated Go/TypeScript bindings; Rust bindings are generated by `servers/crates/delino-protos`.
- `examples/delitools-client`: Go consumer example.
- `apps/delino-docs`: public API usage documentation.

## Cross-Domain Invariants

Shared UI primitives are owned by [the UI package](project-ui.md) at `packages/ui`.

All hosts render an empty root with the `DeliTools` application name and `io.delino.delitools` identifier. The application scaffold has no account access, RPC or product storage. The independent API adds no application integration or UI. Future tools use delcore for usage-based billing; clients do not own billing or service credentials. The web build targets Cloudflare Pages. DeliDev remains a separate application. React, Rsbuild and Rust follow the existing DeliDev shell instead of the default new-project Go language. Mobile uses system webviews; CEF is desktop-only.

## Change Policy

Update this index and the application contract together when paths, targets or release boundaries change. Keep validation results and unperformed native/store checks in commit, PR or CI records. Update instructions only for ownership and development-rule changes.
