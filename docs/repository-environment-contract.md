# Environment contract

Commit only non-sensitive configuration, immutable tool versions and safe service-local examples. Never commit real environment files, credentials, signing material, `.infisical.json` or `.dev-environment/`. Delcore operator configuration belongs to `delinoio/servers`; this repository contains no server configuration or credentials. The shells require no account credentials. Mobile release credentials belong to the protected `delitools-mobile` GitHub environment; configure its secrets, variables and branch restrictions in this repository before dispatch. Secret values cannot be retrieved or migrated through Git.

Release preparation uses repository Actions variable `DELINO_RELEASE_BOT_CLIENT_ID` and secret `DELINO_RELEASE_BOT_PRIVATE_KEY` for the GitHub App installed on `delinoio/apps`. Each web application's `<project>-production` environment owns secret `CLOUDFLARE_API_TOKEN` and variables `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_PAGES_PROJECT`. Configure environment approvals, allowed main/tag refs, Pages production branches and domains outside Git. See the [workflow contract](repository-workflow-contract.md#project-release-preparation) for permissions and release procedures. The shared protected `release-signing` environment owns release signing credentials, including `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` and `APPLE_TEAM_ID`. Application-specific updater keys and source-approval variables retain their application prefixes. The shared protected `release-publish` environment owns final publication approval. Mobile release credentials remain in their existing protected environment.
