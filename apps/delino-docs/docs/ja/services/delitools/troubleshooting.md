# DeliTools の設定とトラブルシューティング

このページでは、DeliTools 用のクライアントの設定方法とエラーの解決方法を説明します。フィールドのルールについては、[API リファレンス](/ja/services/delitools/api-reference)を参照してください。

## クライアントを設定する

- **ベース URL。** サービス運用者から提供された DeliTools API サーバーの URL を使用してください。プロシージャのパスは `/delitools.v1.DelitoolsService/Translate` と `/delitools.v1.DelitoolsService/Extract` です。
- **プロトコル。** Connect クライアントを使用するか、`POST` と `Content-Type: application/json` で JSON を送信してください。JSON のフィールド名には lowerCamelCase を使用します。
- **認証情報。** `Authorization: Bearer <credential>` を送信してください。Delino のログイントークン、または `dlk_` で始まる API キーを使用します。キーはサーバー側のコードで管理してください。DeliTools はブラウザーからの呼び出しをサポートしていません。
- **テナント。** ログイントークンには `tenantId` が必要です。API キーはそれ自体でテナントを識別します。`tenantId` も送信する場合は、そのテナントと一致している必要があります。
- **モデル。** 運用者が許可したモデル識別子を使用してください。抽出では固定のモデルを使用し、`model` フィールドはありません。
- **タイムアウト。** 最大のリクエストに適したクライアントのタイムアウトを設定してください。プロバイダーへの呼び出しには数秒かかることがあり、DeliTools が一時的な障害を再試行する場合もあるため、呼び出し全体にはさらに時間がかかることがあります。運用者が設定した実行タイムアウトを超えたリクエストは `ERROR_REASON_TIMEOUT` を返します。クライアント側のタイムアウトによって先に呼び出しが終了した場合、DeliTools はそれをキャンセルとして扱います。
- **再試行。** `ERROR_REASON_RATE_LIMITED`、`ERROR_REASON_PROVIDER_FAILED`、`ERROR_REASON_DEPENDENCY_UNAVAILABLE`、`ERROR_REASON_TIMEOUT` が発生した場合は、指数バックオフと短いランダムな遅延を使用して再試行してください。各再試行は新しい実行であり、課金対象になる場合があります。[課金](/ja/services/delitools/billing)を参照してください。検証に失敗したリクエストは、変更せずに再試行しないでください。

## エラーを解決する

| 理由                                  | 対処方法                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ERROR_REASON_INVALID_INPUT`          | リクエストを修正してください。空文字列、言語タグ、テナント ID、モデル、およびスキーマが有効な JSON かどうかを確認してください。                                                                                                                                                                                                                      |
| `ERROR_REASON_UNAUTHENTICATED`        | トークンまたはキーを確認してください。入力ミス、有効期限切れ、失効、または削除済みテナントへの所属が原因の可能性があります。シークレットを紛失した場合は、新しいキーを作成してください。有効なキーがすべて突然失敗するようになった場合は、サービス運用者に知らせてください。サービス ID の設定に誤りがあると、キーが無効であるかのように扱われます。 |
| `ERROR_REASON_PERMISSION_DENIED`      | キーに `translate` または `extract` の権限があること、ユーザーがそのテナントで引き続き権限を持っていること、送信する `tenantId` がキーのテナントと一致することを確認してください。                                                                                                                                                                   |
| `ERROR_REASON_BILLING_BLOCKED`        | 残高や更新などの課金の問題を Delcore で解決してから、再試行してください。                                                                                                                                                                                                                                                                            |
| `ERROR_REASON_LIMIT_EXCEEDED`         | 項目数を減らす、テキストを短くする、スキーマを小さくするなどして、送信するデータを減らしてください。大きなジョブは複数のリクエストに分割してください。                                                                                                                                                                                               |
| `ERROR_REASON_RATE_LIMITED`           | 送信のペースを落とし、同時リクエスト数を減らして、少し待ってから再試行してください。                                                                                                                                                                                                                                                                 |
| `ERROR_REASON_MODEL_UNAVAILABLE`      | エラーが `invalid_argument` の場合、そのモデルは許可されていません。別のモデルを選択してください。`failed_precondition` の場合は、モデルの料金を登録するよう運用者に依頼してください。                                                                                                                                                               |
| `ERROR_REASON_UNSUPPORTED_SCHEMA`     | [サポートされているサブセット](/ja/services/delitools/api-reference)に含まれないキーワードを削除してください。ルートはオブジェクトスキーマである必要があります。                                                                                                                                                                                     |
| `ERROR_REASON_PROVIDER_FAILED`        | しばらく待ってから再試行してください。問題が続く場合は、リクエスト ID を添えて運用者に問い合わせてください。                                                                                                                                                                                                                                         |
| `ERROR_REASON_INVALID_OUTPUT`         | 一度再試行してください。再発する場合は、スキーマまたは入力を簡略化してください。この試行は課金対象です。                                                                                                                                                                                                                                             |
| `ERROR_REASON_EXTRACTION_FAILED`      | テキストに必要な情報が不足しています。不足している詳細を追加するか、スキーマ内でそのプロパティを省略可能にしてください。この試行は課金対象です。                                                                                                                                                                                                     |
| `ERROR_REASON_TIMEOUT`                | より小さいリクエストを送信してください。後で再試行してください。                                                                                                                                                                                                                                                                                     |
| `ERROR_REASON_CANCELED`               | クライアントが接続を閉じました。クライアントのタイムアウトやシャットダウンが発生していないか確認してください。                                                                                                                                                                                                                                       |
| `ERROR_REASON_DEPENDENCY_UNAVAILABLE` | 後で再試行してください。DeliTools は認可を確認できない場合、有料の処理を受け付けません。                                                                                                                                                                                                                                                             |

## よくある問題

- **あるリクエストではキーが使えるのに、次のリクエストでは失敗する。** 有効期限が切れたキー、失効したキー、または権限を失ったユーザーに属するキーは、直ちに使えなくなります。`ListApiKeys` で確認してください。
- **理由のない、単なる `resource_exhausted` エラー。** リクエスト本文が、運用者の設定した全体のサイズ制限を超えています。送信するデータを減らしてください。
- **結果が正しくないように見える。** モデルは間違えることがあり、スキーマに従った結果が必ずしも正しいとは限りません。スキーマの `description` フィールドの指示をより明確にし、重要な値を確認してください。
- **予期しない請求が発生する。** 使用量が判明している失敗した試行と、繰り返し送信されたリクエストは課金対象です。[課金](/ja/services/delitools/billing)を参照してください。
- **使用量がまだ表示されない。** 使用量は呼び出しの直後に Delcore に届きます。後でもう一度確認してください。

## サポートを依頼する

レスポンス本文または `X-Delitools-Request-Id` ヘッダーのリクエスト ID、プロシージャ名、時刻、エラー理由を含めてください。API キー、ログイントークン、送信したテキストは送らないでください。
