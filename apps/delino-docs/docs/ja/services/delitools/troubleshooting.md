# DeliTools の設定とトラブルシューティング

このページでは、DeliTools 用のクライアントの設定とエラーの解決方法を説明します。フィールドのルールについては、[API リファレンス](/ja/services/delitools/api-reference)を参照してください。

## クライアントの設定

- **ベース URL。** サービス運用者から提供された DeliTools API サーバーの URL を使用してください。プロシージャのパスは `/delitools.v1.DelitoolsService/Translate` と `/delitools.v1.DelitoolsService/Extract` です。
- **プロトコル。** Connect クライアントを使用するか、`POST` と `Content-Type: application/json` で JSON を送信してください。JSON のフィールド名は lowerCamelCase を使用します。
- **認証情報。** `Authorization: Bearer <credential>` を送信してください。Delino のログイントークン、または `dlk_` で始まる API キーを使用します。キーはサーバー側のコードで保持してください。DeliTools はブラウザーからの呼び出しをサポートしていません。
- **テナント。** ログイントークンには `tenantId` が必要です。API キーはそれ自体でテナントを識別します。`tenantId` も送信する場合は、一致している必要があります。
- **モデル。** 運用者が許可しているモデル識別子を使用してください。抽出では固定のモデルを使用し、`model` フィールドはありません。
- **タイムアウト。** 最大のリクエストに適したクライアントタイムアウトを設定してください。プロバイダーの呼び出しには数秒かかることがあり、DeliTools が一時的な障害に対して再試行する場合もあるため、呼び出し全体にはさらに時間がかかることがあります。運用者が設定した実行タイムアウトを超えたリクエストは `ERROR_REASON_TIMEOUT` を返します。クライアント側のタイムアウトによって先に呼び出しが終了した場合、DeliTools はそれをキャンセルとして扱います。
- **再試行。** `ERROR_REASON_RATE_LIMITED`、`ERROR_REASON_DEPENDENCY_UNAVAILABLE`、`ERROR_REASON_TIMEOUT` の場合、および Connect コードが `unavailable` の `ERROR_REASON_PROVIDER_FAILED` の場合に限り、指数バックオフと短いランダムな待機時間を用いて再試行してください。再試行は毎回新しい実行となり、課金される可能性があります。[課金](/ja/services/delitools/billing)を参照してください。検証に失敗したリクエストは、変更せずに再試行しないでください。

## エラーの解決

| 理由                                  | 対処方法                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ERROR_REASON_INVALID_INPUT`          | リクエストを修正してください。空の文字列、言語タグ、テナント ID、モデル、およびスキーマが有効な JSON かどうかを確認してください。                                                                                                                                                                                                          |
| `ERROR_REASON_UNAUTHENTICATED`        | トークンまたはキーを確認してください。入力ミス、有効期限切れ、取り消し、または削除されたテナントに属している可能性があります。シークレットを紛失した場合は、新しいキーを作成してください。有効なキーがすべて突然失敗するようになった場合は、サービス運用者に知らせてください。サービス ID の設定に誤りがあると、キーが無効と判断されます。 |
| `ERROR_REASON_PERMISSION_DENIED`      | キーに `translate` または `extract` の権限が付与されていること、ユーザーが引き続きテナント内で権限を持っていること、および送信する `tenantId` がキーのテナントであることを確認してください。                                                                                                                                               |
| `ERROR_REASON_BILLING_BLOCKED`        | 残高や更新など、Delcore での課金に関する問題を解決してから再試行してください。                                                                                                                                                                                                                                                             |
| `ERROR_REASON_LIMIT_EXCEEDED`         | 項目数を減らす、テキストを短くする、スキーマを小さくするなど、送信するデータを減らしてください。大きなジョブは複数のリクエストに分割してください。                                                                                                                                                                                         |
| `ERROR_REASON_RATE_LIMITED`           | 送信頻度を下げ、同時リクエスト数を減らし、少し待ってから再試行してください。                                                                                                                                                                                                                                                               |
| `ERROR_REASON_MODEL_UNAVAILABLE`      | エラーが `invalid_argument` の場合、そのモデルは許可されていません。別のモデルを選択してください。`failed_precondition` の場合は、モデルの料金を登録するよう運用者に依頼してください。                                                                                                                                                     |
| `ERROR_REASON_UNSUPPORTED_SCHEMA`     | [サポートされているサブセット](/ja/services/delitools/api-reference)に含まれないキーワードを削除してください。ルートはオブジェクトスキーマである必要があります。                                                                                                                                                                           |
| `ERROR_REASON_PROVIDER_FAILED`        | Connect コードが `unavailable` の場合は、待ってから再試行してください。`internal` の場合、プロバイダーがリクエストを拒否しています。変更せずに再試行せず、リクエストを確認し、リクエスト ID を添えて運用者に連絡してください。                                                                                                             |
| `ERROR_REASON_INVALID_OUTPUT`         | 1 回だけ再試行してください。繰り返し発生する場合は、スキーマまたは入力を簡略化してください。この試行は課金対象です。                                                                                                                                                                                                                       |
| `ERROR_REASON_EXTRACTION_FAILED`      | テキストに必要な情報が不足しています。不足している詳細を提供するか、スキーマ内でそのプロパティを任意項目にしてください。この試行は課金対象です。                                                                                                                                                                                           |
| `ERROR_REASON_TIMEOUT`                | リクエストを小さくしてください。後でもう一度試してください。                                                                                                                                                                                                                                                                               |
| `ERROR_REASON_CANCELED`               | クライアントが接続を閉じました。クライアントのタイムアウトやシャットダウンが発生していないか確認してください。                                                                                                                                                                                                                             |
| `ERROR_REASON_DEPENDENCY_UNAVAILABLE` | 後でもう一度試してください。DeliTools は認可を確認できない場合、有料の処理を拒否します。                                                                                                                                                                                                                                                   |

## よくある問題

- **あるリクエストではキーが機能し、次のリクエストでは失敗する。** 有効期限が切れたキー、取り消されたキー、または権限を失ったユーザーに属するキーは、直ちに使用できなくなります。`ListApiKeys` で確認してください。
- **`invalid_argument` がメッセージ `request body is invalid` とともに返される。** DeliTools が JSON リクエスト本文をデコードできませんでした。本文が完全で有効な JSON であり、各フィールドがドキュメントに記載された型になっていることを確認してください。たとえば、`texts` は文字列の配列である必要があります。このメッセージには問題のあるフィールド名が示されないため、リクエストを [API リファレンス](/ja/services/delitools/api-reference)と比較してください。この場合も、レスポンスにはリクエスト ID が含まれます。
- **理由のない単なる `resource_exhausted` エラー。** リクエスト本文が、運用者の設定した全体のサイズ上限を超えています。送信するデータを減らしてください。
- **結果が正しくないように見える。** モデルは間違えることがあり、スキーマに従った結果が必ずしも正しいとは限りません。スキーマの `description` フィールド内の指示をより明確にし、重要な値を確認してください。
- **予期しない請求。** 使用量が判明している失敗した試行と、繰り返されたリクエストは課金対象です。[課金](/ja/services/delitools/billing)を参照してください。
- **使用量がまだ表示されない。** 使用量は呼び出し後まもなく Delcore に届きます。後でもう一度確認してください。

## サポートへの問い合わせ

レスポンス本文または `X-Delitools-Request-Id` ヘッダーに含まれるリクエスト ID、プロシージャ名、時刻、エラー理由を記載してください。API キー、ログイントークン、送信したテキストは送らないでください。
