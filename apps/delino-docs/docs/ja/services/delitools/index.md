# DeliTools

DeliTools は、Connect API を通じて開発者向けの AI ツールを提供します。バージョン1には2つの同期メソッドがあります。テキスト配列の**翻訳**と、テキストから、お客様のスキーマに従った JSON への**データ抽出**です。各呼び出しは、完成した結果またはエラーを同じレスポンスで返します。ポーリングするジョブも、後から取得する結果もありません。すべてのメソッドは `delitools.v1.DeliToolsService` にあります。

DeliTools は、サーバー側コードまたはコマンドラインから、任意の Connect クライアント、または HTTP 経由のプレーン JSON を使用して呼び出してください。API キーをフロントエンドコードに含めないでください。`DELITOOLS_URL` を DeliTools API サーバーのベース URL に設定します。

## クイックスタート

1. **認証情報を選択します。** Delino のログイントークンを使用するか、`CreateKey` で API キーを作成します。認証と API キーのセクションを参照してください。
2. **テナント ID を確認します。** 利用料金は、`tenantId` に指定した Delino テナントに請求されます。
3. **メソッドを呼び出します。** `Authorization: Bearer <credential>` を付けて呼び出します。

```sh
# Translate two texts into Korean. Detect the input language.
curl --request POST "$DELITOOLS_URL/delitools.v1.DeliToolsService/TranslateTextArray" \
  --header "Content-Type: application/json" \
  --header "Connect-Protocol-Version: 1" \
  --header "Authorization: Bearer $DELITOOLS_KEY" \
  --data '{"tenantId":"<tenant-id>","outputLanguage":"ko","model":"<allowed-model>","texts":["Good morning","Where is the station?"]}'
```

```json
{
  "requestId": "019a0000-0000-7000-8000-000000000001",
  "texts": ["좋은 아침이에요", "역이 어디예요?"]
}
```

JSON では、フィールド名に lowerCamelCase、列挙値に完全名を使用します。

## テキストの翻訳

`TranslateTextArray` は、配列内のすべての文字列を翻訳します。

| フィールド       | 必須   | 意味                                                                                              |
| ---------------- | ------ | ------------------------------------------------------------------------------------------------- |
| `tenantId`       | はい   | 利用料金が請求されるテナントです。正規形の UUID バージョン7（小文字、ハイフン付き）を使用します。 |
| `outputLanguage` | はい   | 翻訳先の BCP 47 言語タグです。たとえば `ko`、`pt-BR`、`zh-Hans` です。                            |
| `inputLanguage`  | いいえ | 翻訳元の BCP 47 言語タグです。省略すると、配列全体で1つの言語が検出されます。                     |
| `model`          | はい   | オペレーターの許可リストにあるモデルです。                                                        |
| `texts`          | はい   | 翻訳する文字列です。                                                                              |
| `idempotencyKey` | いいえ | 冪等性を参照してください。                                                                        |

レスポンスには `requestId` と `texts` が含まれます。これは、元の順序と元の長さを保った翻訳結果です。

ルール:

- 言語の値は BCP 47 タグです。`outputLanguage` は必須です。BCP 47 として有効でないタグ、ASCII 以外の文字を含むタグ、64バイトを超えるタグを指定すると、入力無効エラーが返されます。
- `texts` を空にすることはできず、空の文字列や空白のみの文字列を含めることもできません。
- `inputLanguage` を設定し、それが `outputLanguage` と同じ場合、リクエストは無効です。
- `inputLanguage` を省略すると、DeliTools は配列全体について1つの入力言語を検出します。複数の言語が混在する配列も翻訳されます。検出された言語が `outputLanguage` と同じ場合でも、モデルは各項目を処理します。DeliTools が元の配列を未処理のまま返すことはありません。
- オペレーターの許可リストにあるモデルのみが受け付けられます。それ以外のモデルでは、モデル無効エラーが返されます。Vercel AI Gateway のカタログに存在するモデルが、自動的に許可されることはありません。
- 呼び出しが成功するのは、すべての項目が成功した場合のみです。1つの項目が失敗すると、リクエスト全体が失敗します。DeliTools が部分的な翻訳を返すことはなく、失敗した項目を元のテキストで置き換えることもありません。

## データの抽出

`ExtractDataFromText` は、テキストを読み取り、お客様の JSON スキーマに従った JSON を返します。サービスは固定モデル `gpt-6-luna` を使用します。モデルを選択することはできません。

| フィールド       | 必須   | 意味                                                                                              |
| ---------------- | ------ | ------------------------------------------------------------------------------------------------- |
| `tenantId`       | はい   | 利用料金が請求されるテナントです。正規形の UUID バージョン7（小文字、ハイフン付き）を使用します。 |
| `text`           | はい   | 元のテキストです。空にすることはできず、空白のみにすることもできません。                          |
| `jsonSchema`     | はい   | サポートされるサブセットを使用した、文字列形式の JSON スキーマです。                              |
| `idempotencyKey` | いいえ | 冪等性を参照してください。                                                                        |

レスポンスには `requestId` と `jsonData` が含まれます。これは、DeliTools がお客様のスキーマに対して検証した JSON 文字列です。

```sh
curl --request POST "$DELITOOLS_URL/delitools.v1.DeliToolsService/ExtractDataFromText" \
  --header "Content-Type: application/json" \
  --header "Connect-Protocol-Version: 1" \
  --header "Authorization: Bearer $DELITOOLS_KEY" \
  --data '{"tenantId":"<tenant-id>","text":"Ada Lovelace lives in London.","jsonSchema":"{\"type\":\"object\",\"properties\":{\"name\":{\"type\":\"string\"},\"city\":{\"type\":\"string\"}},\"required\":[\"name\",\"city\"],\"additionalProperties\":false}"}'
```

```json
{
  "requestId": "019a0000-0000-7000-8000-000000000002",
  "jsonData": "{\"name\":\"Ada Lovelace\",\"city\":\"London\"}"
}
```

抽出の仕組み:

- モデルには、テキストに記載されている情報のみを使用するよう指示されます。スキーマが必要とする情報がテキストにない場合、呼び出しは抽出不可能エラーで失敗します。サービスが、スキーマを満たすために値を作り出すことはありません。
- DeliTools は、モデルの出力をサーバー上でお客様のスキーマと照合します。不正な形式の出力やスキーマに適合しない出力は、出力無効エラーを伴う失敗となります。それが結果として返されることはなく、DeliTools が再試行や修復を行うこともありません。
- スキーマの検証とプロンプトは、すべての値が意味的に正しいことを保証するものではありません。抽出されたデータは、利用する前に確認してください。DeliTools は、各値の根拠を返しません。
- DeliTools は、AI モデルを呼び出す前にスキーマを確認します。サポートされるサブセットの範囲外のスキーマでは、スキーマ無効エラーが返され、AI の呼び出しも課金も行われません。

### スキーマのサブセット

DeliTools は、抽出モデルの構造化出力がサポートする JSON スキーマの部分のみを受け付けます。

サポートされるもの:

- ルートのオブジェクト。
- 型 `object`、`array`、`string`、`number`、`integer`、`boolean`、`null`。ネストは最大8階層までです。
- `properties`。すべてのプロパティが `required` に列挙されている必要があります。
- すべてのオブジェクトで `additionalProperties` を `false` に設定します。
- 配列の `items`。
- 任意のスキーマの `description`。
- スカラー値の `enum`。

サポートされず、実行前に拒否されるもの:

- 上記のリストにないキーワード。たとえば `pattern`、`minimum`、`format`、`oneOf` です。
- 任意のプロパティ。オブジェクトのすべてのプロパティが `required` に含まれている必要があります。
- `additionalProperties` を `true` に設定した場合、または欠落している場合。
- 参照: `$ref` と再帰的なスキーマ。
- プロバイダーの制限を超えるスキーマ: 5,000個のプロパティ、1,000個の enum 値、またはプロパティ名と enum 値を合わせて120,000文字。250個を超える値を持つ enum の文字列値は、最大15,000文字までです。

サポートされるスキーマ:

```json
{
  "type": "object",
  "properties": {
    "invoiceNumber": { "type": "string", "description": "The invoice number" },
    "total": { "type": "number" },
    "status": { "type": "string", "enum": ["paid", "unpaid"] },
    "lines": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": { "item": { "type": "string" }, "quantity": { "type": "integer" } },
        "required": ["item", "quantity"],
        "additionalProperties": false
      }
    }
  },
  "required": ["invoiceNumber", "total", "status", "lines"],
  "additionalProperties": false
}
```

`note` が任意のプロパティであり、`pattern` がサポートされていないため、サポートされないスキーマ:

```json
{
  "type": "object",
  "properties": {
    "code": { "type": "string", "pattern": "^[A-Z]{3}$" },
    "note": { "type": "string" }
  },
  "required": ["code"],
  "additionalProperties": false
}
```

## リクエストの動作

- どちらのメソッドも同期です。結果またはエラーを受信するまで、接続を開いたままにしてください。
- すべての成功とすべてのエラーには、UUID バージョン7のリクエスト ID が含まれます。サポートを依頼する際には、その ID を含めてください。成功レスポンスには、結果とリクエスト ID のみが含まれます。モデル、トークン数、請求額は含まれません。利用状況を確認するには、課金を参照してください。
- DeliTools は、一時的な AI プロバイダーのエラーを、オペレーターが設定した上限まで再試行します。不正な形式の出力は再試行せず、自動的に別のモデルへ切り替えることもありません。
- 呼び出しをキャンセルした場合、または切断した場合、DeliTools は AI の呼び出しのキャンセルを試み、それ以上の再試行を停止します。すでに発生した利用は、引き続き計測され、請求されます。
- 入力サイズ、翻訳の項目数、実行タイムアウト、テナントあたりのリクエストレート、テナントあたりの同時リクエスト数の制限は、オペレーターが設定します。これらはデプロイメントの設定であり、固定された製品の制限ではありません。制限を超えたリクエストでは、制限エラーが返されます。

## 認証と API キー

各リクエストで `Authorization: Bearer <credential>` を送信します。どちらのツールでも、2種類の認証情報を使用できます。

- **Delino のログイントークン**（Logto のユーザーアクセストークン）は、サインインしているユーザーとして動作します。
- **DeliTools API キー**は、そのキー種別が示す内容で動作します。

また、すべてのリクエストは、Delcore にあるお客様のテナントに対して確認されます。テナントが有効で、有料の処理の実行を許可されており、課金によっても許可されている必要があります。DeliTools がこれらの確認を完了できない場合、新しい有料の実行を拒否します。

### キー種別と権限

- **個人キー**は1人のユーザーに属します。その権限は、キーの権限とそのユーザーの現在の権限の重なり部分です。ユーザーがテナントへのアクセス権を失うと、そのキーは機能しなくなります。
- **サービスキー**はテナントに属します。作成したユーザーのメンバーシップには依存しません。サービスキーを作成および管理できるのは、テナントの Owner または Admin のみです。
- 各キーには、`CAPABILITY_TRANSLATOR` と `CAPABILITY_EXTRACTOR` のいずれかまたは両方の権限があります。キーは、自身の権限に対応するツールのみを呼び出せます。
- ユーザーは自分の個人キーを管理します。キーの管理には Delino のログイントークンが必要です。API キーでキーを作成または取り消すことはできません。

### キーの管理

- `CreateKey`: `tenantId`、`kind`（`KEY_KIND_PERSONAL` または `KEY_KIND_SERVICE`）、`capabilities`、および任意の `expiresAt` を送信します。
- `ListKeys`: テナントのキーを `kind` で絞り込んで一覧表示します。ページングには `afterId` と `pageSize` を使用します。
- `RevokeKey`: `tenantId` と `keyId` を送信します。

```sh
curl --request POST "$DELITOOLS_URL/delitools.v1.DeliToolsService/CreateKey" \
  --header "Content-Type: application/json" \
  --header "Connect-Protocol-Version: 1" \
  --header "Authorization: Bearer $DELINO_TOKEN" \
  --data '{"tenantId":"<tenant-id>","kind":"KEY_KIND_SERVICE","capabilities":["CAPABILITY_TRANSLATOR"]}'
```

- **一度だけ表示されるシークレット。** `CreateKey` のレスポンスには、`secret` が一度だけ含まれます。DeliTools は検証用ハッシュのみを保存しており、シークレットを再び表示することはできません。キーを紛失した場合は、新しいキーを作成してください。シークレットはシークレットマネージャーに保管してください。
- **有効期限。** `expiresAt` は任意です。有効期限のないキーは、取り消すまで有効です。個人キーでは、所有者がテナントへのアクセス権を保持していることも必要です。サービスキーは作成したユーザーに依存しないため、そのユーザーを削除しても停止しません。サービスキーを取り消すか、有効期限を設定してください。
- **取り消し。** キーを取り消した後、または個人キーやログイントークンのユーザーが権限を失った後は、新しいリクエストが拒否され、実行中の呼び出しは AI の再試行を行わなくなります。すでに実行中の呼び出しは完了できます。その利用は請求されます。

## 課金

DeliTools は利用状況を Delcore に報告します。Delcore が USD で料金を計算し、精算します。

- **基準。** 基準となるのは、Vercel AI Gateway のモデルカタログにあるモデルの公開トークン価格に、呼び出しで実際に計測されたトークン数を掛けた金額です。Gateway の割引やプロモーションクレジットによって、基準額が減ることはありません。
- **上乗せ。** 翻訳の料金は、基準額の1.15倍です。抽出の料金は、基準額の1.30倍です。金額は正確な小数と Delcore の丸めルールを使用します。
- **価格の変更。** DeliTools は、カタログの価格を自動的に更新します。新しい価格は、それが有効になった後に開始するリクエストについて、すべてのお客様に適用されます。リクエストは、すべての再試行を通じて、開始時点の価格を維持します。DeliTools がモデルの価格を持っていない場合、新しい AI の実行を拒否します。
- **失敗も課金対象です。** 再試行、失敗した呼び出し、タイムアウト、キャンセル、およびお客様が受信できなかった結果で使用されたトークンも、上乗せ分とともにカウントされます。
- **不明な利用。** DeliTools が呼び出しの利用状況をすぐに読み取れない場合、請求を保留し、後で Gateway と照合します。請求のために利用状況を推定することはありません。レコードが30日後に期限切れになる時点でも利用状況が不明な場合、その請求は破棄されます。
- **利用状況の確認場所。** レスポンスには利用状況が含まれません。利用状況と請求を確認するには、テナントの Delino 課金インターフェースを使用してください。
- **ブロックされたテナント。** 課金によってテナントがブロックされた場合、新しい実行は課金ブロックエラーで失敗します。すでに実行中の呼び出しは中断されません。DeliTools は実行後に利用状況を計測するため、ブロックが適用される前に、同時実行の呼び出しが残高や上限を超えることがあります。

## 冪等性

`idempotencyKey` は任意です。指定しない場合、すべての呼び出しは新しい実行となり、ネットワーク障害後に再試行する場合を含めて、新しい請求が発生することがあります。

キーを指定すると、DeliTools は**テナント、メソッド、キー**でリクエストを追跡します。これは、同じテナントの異なる認証情報にまたがって適用されます。DeliTools は、リクエストの状態をお知らせする前に、現在の権限を確認します。

| 状況                                           | 結果                                                                               |
| ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| 新しいキー                                     | 呼び出しは通常どおり実行されます。                                                 |
| 同じキーと同じ入力で、実行中                   | 最初の呼び出しのリクエスト ID を含む処理中エラーです。待機はしません。             |
| 同じキーと同じ入力で、完了済み                 | 処理済みエラーです。結果は再現されません。                                         |
| 同じキーで入力が異なる                         | 入力競合エラーです。                                                               |
| 最初の呼び出しが不明な状態で終了した           | 結果不明エラーです。DeliTools が AI の呼び出しを自動的に繰り返すことはありません。 |
| 30日間のレコードが期限切れになった後の同じキー | 新しい呼び出しとなり、通常どおり請求されます。                                     |

DeliTools は、キー、入力のハッシュ、および状態を保持します。入力や結果は保持しません。重複排除が有効なのは、最初の呼び出しから30日間のみです。結果は受信したときに保存してください。同じキーでの繰り返しの呼び出しでは、結果を再び返すことはできません。

## エラー

すべてのエラーには、Connect コード、安定した理由、リクエスト ID、および英語のメッセージがあります。理由とリクエスト ID は、`delitools.v1.ErrorDetail` エラー詳細に含まれます。コードでは、メッセージではなく理由を使用してください。

| 理由                                 | Connect コード        | 意味                                                                                 |
| ------------------------------------ | --------------------- | ------------------------------------------------------------------------------------ |
| `ERROR_REASON_INVALID_INPUT`         | `invalid_argument`    | リクエストが無効です。たとえば、空の配列や同一の言語です。                           |
| `ERROR_REASON_INVALID_SCHEMA`        | `invalid_argument`    | スキーマがサポートされるサブセットの範囲外です。                                     |
| `ERROR_REASON_INVALID_MODEL`         | `invalid_argument`    | モデルが許可リストにありません。                                                     |
| `ERROR_REASON_UNAUTHENTICATED`       | `unauthenticated`     | 認証情報がない、無効、期限切れ、または取り消されています。                           |
| `ERROR_REASON_FORBIDDEN`             | `permission_denied`   | この認証情報またはユーザーは、このテナントでこのツールを使用できません。             |
| `ERROR_REASON_BILLING_BLOCKED`       | `failed_precondition` | 課金により、このテナントの新しい有料の実行が許可されていません。                     |
| `ERROR_REASON_PRICE_UNAVAILABLE`     | `failed_precondition` | モデルの公開価格が利用できないため、DeliTools はそのモデルを実行しません。           |
| `ERROR_REASON_LIMIT`                 | `resource_exhausted`  | 設定された制限を超えました。入力サイズ、項目数、レート、同時実行数などです。         |
| `ERROR_REASON_PROCESSING`            | `aborted`             | 同じ冪等性キーのリクエストがまだ実行中です。                                         |
| `ERROR_REASON_ALREADY_PROCESSED`     | `already_exists`      | 同じ冪等性キーと入力のリクエストがすでに完了しています。                             |
| `ERROR_REASON_INPUT_CONFLICT`        | `failed_precondition` | 冪等性キーが異なる入力で使用されました。                                             |
| `ERROR_REASON_UNKNOWN_OUTCOME`       | `unknown`             | 最初の実行の結果が不明です。                                                         |
| `ERROR_REASON_EXTRACTION_IMPOSSIBLE` | `failed_precondition` | テキストに、スキーマが必要とする情報が含まれていません。                             |
| `ERROR_REASON_INVALID_OUTPUT`        | `data_loss`           | モデルが、不正な形式の出力、またはスキーマに一致しない出力を返しました。             |
| `ERROR_REASON_PROVIDER`              | `unavailable`         | 許可された再試行の後も、AI プロバイダーで障害が発生しました。                        |
| `ERROR_REASON_TIMEOUT`               | `deadline_exceeded`   | 実行タイムアウトを超過しました。                                                     |
| `ERROR_REASON_CANCELED`              | `canceled`            | 呼び出しがキャンセルされました。                                                     |
| `ERROR_REASON_INTERNAL`              | `internal`            | 内部障害です。たとえば、ストレージでの障害です。                                     |
| `ERROR_REASON_INTERNAL`              | `unavailable`         | テナントの認可または課金の確認を完了できなかったため、新しい有料処理は拒否されます。 |

対処方法:

- `invalid_argument`、`permission_denied`、`unauthenticated`、`failed_precondition` のエラーでは、再試行する前にリクエストを修正してください。課金ブロックエラーでは、課金のブロックを解消してください。
- プロバイダー、タイムアウト、または内部のエラーは、後で再試行できます。プロバイダーとタイムアウトの失敗は、引き続き請求されることがあります。最初の実行が成功していた可能性がある場合に2回目の実行を避けるには、冪等性キーを使用してください。 `unavailable` と `ERROR_REASON_INTERNAL` の組み合わせは、DeliTools が認可または課金の確認を完了できなかったことを意味します。`ERROR_REASON_INTERNAL` は `internal` でも返されるため、コードと理由の両方で分岐してください。
- 結果不明、処理中、処理済みのエラーには、最初の呼び出しのリクエスト ID が含まれます。結果が不明なままの場合は、その ID を添えてサポートに問い合わせてください。

## データの保持

DeliTools が、お客様の入力テキスト、スキーマ、結果を保存することはありません。ログ、トレース、監査イベントにも含めません。認証情報とシークレットは、テレメトリから除外されます。

DeliTools が保存するのは、サービスの運用と課金に必要なデータのみです。API キーの検証用ハッシュ、リクエストの所有者であるユーザーとテナント、冪等性のための入力ハッシュ、リクエストの状態、試行の識別子、計測されたトークン使用量、価格のスナップショット、および安全な監査記録と運用記録です。

| データ                               | 保持期間                           |
| ------------------------------------ | ---------------------------------- |
| 冪等性レコード                       | 最初の作成から30日間               |
| 利用状況の配信および照合レコード     | 最初の作成から30日間               |
| プラットフォームの監査記録と運用ログ | 作成から30日間                     |
| API キー                             | 30 日間の保持では削除されません    |
| Delcore で受理された会計エントリ     | Delcore 独自の保持ルールに従います |

30 日間の保持は API キーには適用されません。保持処理が API キーを削除することはありません。有効期限の経過や取り消しは、キーの認証を止めるだけなので、検証用ハッシュと帰属情報は保存されたままです。

30日間は、レコードが最初に作成された時点から始まります。再試行や状態の変更によって延長されることはありません。DeliTools は、完了しなかったリクエストや未配信の利用状況を含め、あらゆる状態のレコードを、期限切れになった時点で削除します。お客様は次の2つのリスクを受け入れるものとします。

- 冪等性レコードの期限が切れた後に、同じキーで呼び出しを繰り返すと、その呼び出しは実行され、再び請求されます。
- レコードの期限が切れた時点でまだ保留中の利用状況は失われ、DeliTools はそれを請求しません。

## 外部プロバイダーのデータの取り扱い

サービスを提供するために、DeliTools は、お客様のテキストと、抽出の場合はお客様のスキーマを、Vercel AI Gateway に送信し、そこから、お客様のリクエストを実行するモデルのプロバイダーに送信します。これらのサービスは、それぞれ独自のポリシーに従ってデータを取り扱います。DeliTools にデータを送信する前に、それらを確認してください。

- [Vercel AI Gateway zero data retention](https://vercel.com/docs/ai-gateway/security-and-compliance/zdr)
- [Vercel AI Gateway models](https://vercel.com/ai-gateway/models): 各モデルのページに、そのプロバイダーが記載されています。
- 使用するモデルのプロバイダーのデータポリシー。

DeliTools は、どのプロバイダーにおいてもゼロデータ保持を約束しません。機密データを検出することも、お客様の入力から削除することもありません。これらのプロバイダーと共有してはならないデータを送信しないでください。

## 制限

DeliTools API サーバーのオペレーターは、入力サイズ、翻訳の項目数、実行タイムアウト、テナントあたりの毎分のリクエスト数、テナントあたりの同時リクエスト数、AI の再試行回数、および翻訳モデルの許可リストの制限を設定します。これらはデプロイメントの設定であり、変更されることがあります。固定された製品の制限ではなく、DeliTools はスループットや可用性を保証しません。制限を超えたリクエストでは `ERROR_REASON_LIMIT` が返され、無効なモデルの場合は `ERROR_REASON_INVALID_MODEL` が返されます。現在の値については、お使いのデプロイメントのオペレーターに問い合わせてください。
