# DeliTools API キー

API キーを使うと、サーバーから Delino のログイントークンなしで DeliTools を呼び出せます。Delcore はすべての Delino サービスのキーを作成・検証するため、同じキーの仕組みを他のサービスでも利用できます。キーの管理には Delino のログイントークンを使い、サービスを呼び出す際にはキーを Bearer トークンとして使います。

## キーの種類

| 種類                 | 動作主体                           | 作成、一覧表示、失効を行えるユーザー                                 | 使用時の権限                                                                                           |
| -------------------- | ---------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 個人キー             | 1 つのテナント内でのあなた自身     | あなた自身のみ。ただし、そのテナントの現メンバーである間に限ります。 | キーに付与された権限と、あなたの現在のテナント内の権限。両方で呼び出しが許可されている必要があります。 |
| テナントサービスキー | ユーザーに依存しない、テナント自体 | そのテナントの現在の Owner または Admin。                            | キーに付与された権限のみ。作成者が脱退しても引き続き機能します。                                       |

- Owner や Admin を含め、他のユーザーがあなたの個人キーを表示したり失効させたりすることはできません。Billing ロールと Member ロールはテナントサービスキーを管理できません。
- マシン間通信用の ID はキーを管理できません。キーは、権限が付与されたサービスでのみ使用でき、Delcore 自体の認証情報としては使用できません。
- どちらの種類も 1 つのテナントに紐づきます。キーを別のテナントに使用することはできません。

## キーの作成

Delino のログイントークンを使って、`https://delcore.api.delino.io` の `delcore.v1.DelcoreService/CreateApiKey` を呼び出します。

| フィールド   | ルール                                                                                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requestKey` | 自分で生成した UUID v7。同じキーと入力でリクエストを繰り返すと、同じ結果が返されます。                                                                                              |
| `tenantId`   | キーが属するテナント。                                                                                                                                                              |
| `ownerKind`  | `API_KEY_OWNER_KIND_PERSONAL` または `API_KEY_OWNER_KIND_TENANT`。                                                                                                                  |
| `name`       | 1～100 バイト。空白のみは不可で、制御文字を含めることはできません。                                                                                                                 |
| `grants`     | 1～16 件の権限付与。各項目には `serviceId` と、各最大 100 バイトの `capabilities` を 1～32 個指定します。同じサービスを複数回指定することはできず、ケイパビリティも重複できません。 |
| `expiresAt`  | 省略可能な、RFC 3339 形式の未来の時刻。省略すると、失効させるまでキーは有効です。                                                                                                   |

サービスの `serviceId` とケイパビリティは、Delcore カタログ（`GetCatalog`）で確認してください。DeliTools では、必要に応じて `translate` と `extract` のケイパビリティを付与します。Delcore はサービスが宣言したケイパビリティのみを受け付けるため、入力を誤ったケイパビリティはキーの作成時に拒否されます。

```sh
curl --request POST "https://delcore.api.delino.io/delcore.v1.DelcoreService/CreateApiKey" \
  --header "Content-Type: application/json" \
  --header "Authorization: Bearer $DELINO_TOKEN" \
  --data '{"requestKey":"<uuid-v7>","tenantId":"<tenant-id>","ownerKind":"API_KEY_OWNER_KIND_TENANT","name":"Production translation","grants":[{"serviceId":"<deli-tools-service-id>","capabilities":["translate"]}],"expiresAt":"2027-01-01T00:00:00Z"}'
```

レスポンスにはキーの詳細と、`dlk_` で始まる `secret` が含まれます。

- **シークレットが表示されるのは一度だけです。** その場でシークレットマネージャーにコピーしてください。Delcore はハッシュのみを保持し、一覧や再リクエストのレスポンスにシークレットを表示することはありません。
- **シークレットを紛失した場合。** シークレットを紛失した場合、または再リクエストのレスポンスで `secret` が空の場合は、新しいキーを作成し、古いキーを失効させてください。
- **パスワードと同様に扱ってください。** サーバー側のコード内で保持し、ログ、リポジトリ、フロントエンドのバンドルに含めないでください。
- 各テナントで有効にできるキーの数には上限があります。個人キーはユーザーごとに 20 個、テナントキーは合計 20 個です。失効済みおよび期限切れのキーは数に含まれません。

付与する権限と有効期限は、キーの作成時に固定されます。編集、更新、ローテーションのための呼び出しはありません。キーを変更するには、新しい権限や有効期限を指定して代わりのキーを作成し、アプリケーションをそのキーに切り替えてから、古いキーを失効させてください。

## キーの一覧表示と失効

- `ListApiKeys` は `tenantId` と `ownerKind` を受け取ります。失効済みや期限切れのキーを含むキーの詳細を返しますが、シークレットは決して返しません。個人キーの一覧には自分のキーのみが表示されます。テナントキーの一覧表示には Owner または Admin ロールが必要です。続きを取得するには、返された `nextAfterId` を `page.afterId` に指定してください。
- `RevokeApiKey` は `requestKey`、`tenantId`、`keyId` を受け取ります。新しいリクエストに対して即座に有効になります。再度失効させても問題ありません。

## キーの使用

キーで権限が付与されたサービスに、シークレットを `Authorization: Bearer dlk_...` として送信します。DeliTools では、[API リファレンス](/ja/services/delitools/api-reference)に記載されているとおり、`Translate` と `Extract` で使用できます。

- キーを使用する場合、`tenantId` は省略可能です。送信する場合は、キーのテナントと一致している必要があります。
- キーは、そのサービスに対して付与されたケイパビリティのみを使用できます。あるサービス用のキーを別のサービスで使うことはできません。
- Delcore はリクエストごとにキーを検証し、さらに AI の各再試行の前にも検証します。失効、有効期限切れ、権限または課金機能へのアクセスの喪失により、新しいリクエストとそれ以降の再試行は停止します。すでに実行中のプロバイダーへの呼び出しは完了できます。
- 個人キーは、テナントから削除された場合やグループの権限を失った場合など、テナント内でそのケイパビリティを使用する権限がなくなっている間は機能しなくなります。あなたが削除されても、キー自体は削除されません。
- テナントキーは、作成者がメンバーであるかどうかには依存しません。
- キーを使った呼び出しは、ログイントークンを使った呼び出しと同じ料金で、キーのテナントに課金されます。[課金](/ja/services/delitools/billing)を参照してください。
- テナントを削除すると、削除が確定した時点で Delcore がそのキーを削除します。個人キーは、ユーザーの退会が受理されると直ちに削除されます。削除済みテナントのキーは無効です。

## よくあるエラー

| 状況                                                                     | 結果                                                                   |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| シークレットの入力誤り、不明なシークレット、失効済み、または期限切れ     | `unauthenticated`。Delcore はどれに該当するかを示しません。            |
| キーにサービスまたはケイパビリティの権限がない                           | `permission_denied`                                                    |
| `tenantId` がキーのテナントと一致しない                                  | `permission_denied`                                                    |
| 自分のロールではこの種類のキーを管理できない                             | 作成、一覧表示、失効の際に Delcore が `permission_denied` を返します。 |
| 他のユーザーの個人キー、または不明なキーを失効させる                     | Delcore が `not_found` を返します。                                    |
| 削除処理中のテナントでキーを作成する、またはキー数の上限を超えて作成する | Delcore が `failed_precondition` を返します。                          |
| 権限付与、名前、サービス、ケイパビリティ、または有効期限が無効           | キーの作成時に Delcore が `invalid_argument` を返します。              |
| テナントの課金がブロックされている                                       | DeliTools が `ERROR_REASON_BILLING_BLOCKED` を返します。               |
