# DeliTools API キー

API キーを使うと、Delino のログイントークンなしでサーバーから DeliTools を呼び出せます。Delcore はすべての Delino サービスのキーを作成・検証するため、同じキーの仕組みをほかのサービスでも利用できます。キーの管理には Delino のログイントークンを使用し、サービスを呼び出す際にはキーを Bearer トークンとして使用します。

## キーの種類

| 種類                 | 動作主体                           | 作成・一覧表示・取り消しができる人                                   | 使用時の権限                                                                                     |
| -------------------- | ---------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 個人キー             | 1 つのテナント内のあなた自身       | あなただけ。ただし、そのテナントの現在のメンバーである間に限ります。 | キーに付与された権限と、あなたの現在のテナント権限。両方が呼び出しを許可している必要があります。 |
| テナントサービスキー | ユーザーに依存しない、テナント自体 | テナントの現在の Owner または Admin。                                | キーに付与された権限のみ。作成者が脱退しても引き続き機能します。                                 |

- Owner や Admin を含め、ほかのユーザーがあなたの個人キーを表示したり取り消したりすることはできません。Billing および Member ロールでは、テナントサービスキーを管理できません。
- マシン間通信用の ID ではキーを管理できません。キーは Delcore 自体の認証情報としては一切使用できず、権限を付与されたサービスでのみ使用できます。
- どちらの種類も 1 つのテナントに紐づきます。別のテナントでキーを使用することはできません。

## キーを作成する

Delino のログイントークンを使用して、`https://delcore.api.delino.io` の `delcore.v1.DelcoreService/CreateApiKey` を呼び出します。

| フィールド   | ルール                                                                                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requestKey` | 自分で生成する UUID v7。同じキーと入力でリクエストを繰り返すと、同じ結果が返されます。                                                                                       |
| `tenantId`   | キーが属するテナント。                                                                                                                                                       |
| `ownerKind`  | `API_KEY_OWNER_KIND_PERSONAL` または `API_KEY_OWNER_KIND_TENANT`。                                                                                                           |
| `name`       | 1～100 バイト。空白のみは不可で、制御文字を含めることはできません。                                                                                                          |
| `grants`     | 1～16 件の権限付与。各項目は `serviceId` と、各 100 バイト以下の `capabilities` を 1～32 個持ちます。同じサービスは 1 回のみ指定でき、ケイパビリティの重複は認められません。 |
| `expiresAt`  | 任意。RFC 3339 形式の将来の日時。指定しない場合、取り消すまでキーは有効です。                                                                                                |

サービスの `serviceId` とケイパビリティは、Delcore カタログ（`GetCatalog`）で確認できます。DeliTools では、必要に応じて `translate` と `extract` のケイパビリティを付与します。Delcore はサービスが宣言したケイパビリティのみを受け付けるため、ケイパビリティに入力ミスがあると、キーの作成時に拒否されます。

```sh
curl --request POST "https://delcore.api.delino.io/delcore.v1.DelcoreService/CreateApiKey" \
  --header "Content-Type: application/json" \
  --header "Authorization: Bearer $DELINO_TOKEN" \
  --data '{"requestKey":"<uuid-v7>","tenantId":"<tenant-id>","ownerKind":"API_KEY_OWNER_KIND_TENANT","name":"Production translation","grants":[{"serviceId":"<deli-tools-service-id>","capabilities":["translate"]}]}'
```

この例では有効期限を設定していないため、取り消すまでキーは有効です。有効期限を追加するには、`expiresAt` に RFC 3339 形式の将来の日時を設定します。

レスポンスには、キーの詳細と、`dlk_` で始まる `secret` が含まれます。

- **シークレットは一度しか表示されません。** その場でシークレットマネージャーにコピーしてください。Delcore はハッシュのみを保持し、一覧や繰り返しのレスポンスにシークレットを表示することはありません。
- **シークレットを紛失した場合。** シークレットを紛失した場合、または繰り返したリクエストのレスポンスで `secret` が空の場合は、新しいキーを作成し、古いキーを取り消してください。
- **パスワードと同様に扱ってください。** サーバー側のコードで保持し、ログ、リポジトリ、フロントエンドのバンドルには含めないでください。
- 上限：有効な個人キーはユーザーとテナントの組み合わせごとに 100 個、有効なテナントキーはテナントごとに 100 個まで保持できます。取り消し済みおよび期限切れのキーは有効なキーとして数えられませんが、30 日間保持されます。1 つのスコープに保持できるキーは、すべての状態を合わせて最大 500 個です。

付与する権限と有効期限は、キーの作成時に確定します。編集、更新、ローテーション用の呼び出しはありません。キーを変更するには、新しい権限または有効期限を指定して代わりのキーを作成し、アプリケーションで使用するキーを切り替えてから、古いキーを取り消します。

## キーの一覧表示と取り消し

- `ListApiKeys` は `tenantId` と `ownerKind` を受け取ります。取り消し済みおよび期限切れのキーを含むキーの詳細を返しますが、シークレットは一切返しません。個人キーの一覧には、自分自身のキーのみが表示されます。テナントキーの一覧表示には Owner または Admin ロールが必要です。さらに取得するには、返された `nextAfterId` を `page.afterId` に指定します。
- `RevokeApiKey` は `requestKey`、`tenantId`、`keyId` を受け取ります。取り消しは、新しいリクエストに対して即座に有効になります。再度取り消しを行っても問題ありません。

## キーを使用する

キーで権限を付与されたサービスに、シークレットを `Authorization: Bearer dlk_...` として送信します。DeliTools では、[API リファレンス](/ja/services/delitools/api-reference)に記載されているとおり、`Translate` と `Extract` で使用できます。

- キーを使用する場合、`tenantId` は任意です。送信する場合は、キーのテナントと一致している必要があります。
- キーは、そのサービスに対して付与したケイパビリティのみを使用できます。あるサービス用のキーを別のサービスで使用することは一切できません。
- Delcore は、すべてのリクエスト時と、AI の各再試行の前にキーを検証します。取り消し、有効期限切れ、権限または課金アクセスの喪失により、新しいリクエストと以降の再試行は停止します。すでに実行中のプロバイダー呼び出しは完了する場合があります。
- 個人キーは、テナントから削除されたり、グループ権限を失ったりするなど、テナント内でそのケイパビリティを使用する権限がなくなっている間は機能しません。テナントから削除されても、キーは削除されません。
- テナントキーは、作成者がメンバーであるかどうかには依存しません。
- キーを使った呼び出しは、ログイントークンを使った呼び出しと同じ料金で、キーのテナントに課金されます。[課金](/ja/services/delitools/billing)を参照してください。
- テナントを削除すると、削除が確定した時点で Delcore がそのキーを削除します。個人キーは、ユーザーの退会が受理され次第削除されます。削除されたテナントのキーは無効です。

## よくあるエラー

| 状況                                                                               | 結果                                                                     |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| シークレットに入力ミスがある、不明である、取り消し済みである、または期限切れである | `unauthenticated`。Delcore は、これらのどれに該当するかを明かしません。  |
| キーにサービスまたはケイパビリティの権限がない                                     | `permission_denied`                                                      |
| `tenantId` がキーのテナントと一致しない                                            | `permission_denied`                                                      |
| 自分のロールではこの種類のキーを管理できない                                       | 作成・一覧表示・取り消し時に Delcore が `permission_denied` を返します。 |
| 別のユーザーの個人キー、または不明なキーを取り消す                                 | Delcore が `not_found` を返します。                                      |
| 削除処理中のテナントでキーを作成する、またはキーの上限を超えて作成する             | Delcore が `failed_precondition` を返します。                            |
| 権限付与、名前、サービス、ケイパビリティ、または有効期限が無効である               | キーの作成時に Delcore が `invalid_argument` を返します。                |
| テナントの課金がブロックされている                                                 | DeliTools が `ERROR_REASON_BILLING_BLOCKED` を返します。                 |
