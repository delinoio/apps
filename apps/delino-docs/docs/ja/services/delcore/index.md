# Delcore

Delcore は、Delino サービス向けに共有テナント、アクセス制御、請求機能を提供します。公式 API サーバーは `https://delcore.api.delino.io` です。このページでは、サービス開発者向けに API キーの検証、使用量の料金、レコードの有効期限、テナント状態の確認について説明します。

## テナント状態の確認

登録済みのサービスは、テナントが有効、ブロック済み、削除済みのいずれであるかを Delcore に問い合わせることができます。サービスがテナントのデータを保存しているものの、各リクエストに対応する Delino ユーザーが存在しない場合、たとえばプロジェクトの API キーで呼び出す場合に、この確認を使用してください。

1～100 件のテナント ID を指定して `delcore.v1.DelcoreService/GetTenantStates` を呼び出します。各 ID は小文字の UUID バージョン 7 でなければなりません。サービスの Logto マシン間アプリケーションのアクセストークンで認証してください。サービスは Delcore に登録されており、`authorize` スコープを持っている必要があります。ユーザートークン、未登録のサービス、このスコープを持たないサービスでは、テナント状態を読み取れません。

レスポンスには、リクエストした各テナント ID が送信順に含まれ、それぞれに次のいずれかの状態が付与されます。

| 状態                    | 意味                                                           |
| ----------------------- | -------------------------------------------------------------- |
| `TENANT_STATE_ACTIVE`   | テナントが存在し、ブロックされておらず、削除中でもありません。 |
| `TENANT_STATE_BLOCKED`  | プラットフォーム運用担当者がテナントをブロックしました。       |
| `TENANT_STATE_DELETING` | 削除待ちです。                                                 |
| `TENANT_STATE_DELETED`  | 削除が確定しています。                                         |
| `TENANT_STATE_UNKNOWN`  | Delcore にこの ID のテナントは存在しません。                   |

複数の条件が該当する場合、`DELETED` は `DELETING` より優先され、`DELETING` は `BLOCKED` より優先され、`BLOCKED` は `ACTIVE` より優先されます。

状態は請求状況に依存しません。サブスクリプションの期限切れ、更新の失敗、異議申し立て、残高不足によってテナントが `BLOCKED` になることはありません。ユーザーが有料の処理を実行できるかどうかを判断するには、代わりに `Authorize` を使用してください。この確認はデータの読み取りのみを行います。テナントの変更、有料利用の承認、決済プロバイダーへの連絡は行わず、テナント名、ユーザーの詳細、請求情報も返しません。

## 結果と障害への対応

- アクセスを許可するのは、`TENANT_STATE_ACTIVE` の場合、またはオーナーや管理者向けに独自に文書化したルールで、ブロック済みまたは削除中のテナントへのアクセスが認められる場合に限ってください。
- `TENANT_STATE_UNKNOWN`、リクエストエラー、タイムアウト、Delcore が利用できない場合は、アクセス不可として扱ってください。これらの場合にデータを削除しないでください。
- テナント削除に伴うクリーンアップでは、明示的な `TENANT_STATE_DELETED` を受け取った後にのみ、保持しているテナントデータを自動的に削除してください。`BLOCKED` と `DELETING` は、このクリーンアップを決して許可しません。固定のレコード有効期限は、テナント状態とは独立して適用されます。
- 無効な ID、空のリクエスト、100 件を超える ID は、無効な引数のエラーを返します。認証情報が欠落している、期限切れである、または無効である場合は、未認証エラーを返します。テナント状態の読み取りを許可されていない呼び出し元には、権限拒否エラーが返されます。その他の障害では、相関 ID を含むエラーが返されます。サポートを依頼する際は、エラーの詳細と `X-Delcore-Correlation-Id` ヘッダーに記載されているこの ID を含めてください。
- 失敗したリクエストは後で再試行してください。リクエストの失敗が、テナントが有効または削除済みであることを意味することはありません。

## 使用量の料金とレコードの有効期限

使用量の単価は、既存の契約者を含むすべての顧客について、初回の実行開始時点で適用されます。その開始時点を `IngestEvent` の `occurred_at` として報告し、実行の再試行や使用量の照合でも維持してください。価格変更は、それ以降の実行に適用されます。配信の遅延や訂正があっても、元の価格の適用は維持されます。定期支払いの料金、選択された機能、含まれる使用量の付与分については、サブスクリプションの条件が維持されます。

リクエストの重複排除は、レコードの初回作成から 30 日間有効です。再試行してもこの期間は延長されません。期限が切れると、同じリクエストキーで、現在の権限と、独立した支払いまたはイベントの識別チェックに従って、新しい操作を開始できます。受理された使用量イベントは、会計処理への重複した反映を防ぐため、永続的な識別情報を保持します。

利用側のサービスは、実行または使用量が不明なままである場合や、レポートが Delcore に届いていない場合でも、使用量の配信および照合のレコードを初回作成から 30 日後に削除しなければなりません。その期限までは配信と不明な使用量の照会を再試行し、その後は保留中の請求を断念してください。請求のために使用量を推定しないでください。これにより、請求可能な使用量が恒久的に失われる可能性があり、実行の重複排除キーの期限切れによって、新たな実行と請求が可能になることがあります。プラットフォームの監査レコードと運用ログも、作成から 30 日後に期限切れになります。これらの制限は、Delcore がすでに受理した会計エントリを削除したり、API キーの有効性を変更したりするものではありません。

## API キーの検証

Delcore は、登録済みのあらゆるサービス向けに、再利用可能な個人用およびテナントサービス用の API キーを発行します。ユーザー、およびテナントのオーナーと管理者は、Delino ログイントークンを使用してキーを作成します。ユーザー向けの手順については、[DeliTools API キー](/ja/services/delitools/api-keys)を参照してください。キーは `dlk_` で始まり、選択されたサービスの選択されたケイパビリティを付与し、1 つのテナントに属します。

登録済みのサービスは、呼び出し元から受け取ったキーを `delcore.v1.DelcoreService/AuthorizeApiKey` で検証します。サービスの Logto マシン間アクセストークンで認証してください。サービスは登録済みで、`authorize` スコープを持っている必要があります。

- 完全な `secret`、使用する `capability`、有料の処理の場合は `paid` を送信してください。`Authorize` と同様に、`feature_key` と `group_values` も送信できます。
- Delcore は、呼び出し元のサービスを指定している権限付与のみを評価するため、サービスが別のサービスのケイパビリティを承認することは決してできません。
- 形式が不正、不明、取り消し済み、期限切れのシークレット、または削除済みテナントのシークレットは、未認証エラーを返し、キーの詳細は返しません。サービス自身のトークンが拒否された場合も Delcore は同じ応答を返すため、有効なキーがすべて失敗する場合は、サービスの認証情報を確認してください。これは無効な認証情報として扱ってください。
- 有効なシークレットの場合、レスポンスには `allowed`、`reasons`、任意の `feature` に加えて、`keyId`、`tenantId`、`ownerKind`、`userId` が含まれます。ケイパビリティを持たないキーは、`BLOCK_REASON_PERMISSION` とともに `allowed: false` を返します。
- 個人用キーには、テナント内でそのケイパビリティに対するユーザーの現在の権限も必要です。テナントキーは、作成したユーザーに依存しません。どちらも有効なテナントが必要であり、`paid` が設定されている場合は `Authorize` と同じ請求チェックが必要です。
- 呼び出し元がテナントを指定している場合は、返された `tenantId` と比較し、一致しなければ拒否してください。
- すべてのリクエストで確認してください。結果をキャッシュしないでください。エラー、タイムアウト、Delcore が利用できない場合は、新たな有料の処理へのアクセス不可として扱ってください。認可結果は何も予約しません。
