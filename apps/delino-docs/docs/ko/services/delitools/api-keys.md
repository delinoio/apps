# DeliTools API 키

API 키를 사용하면 서버에서 Delino 로그인 토큰 없이 DeliTools를 호출할 수 있습니다. Delcore는 모든 Delino 서비스의 키를 생성하고 검증하므로, 다른 서비스에서도 동일한 키 기능을 사용할 수 있습니다. 키는 Delino 로그인 토큰으로 관리하며, 서비스를 호출할 때는 키를 Bearer 토큰으로 사용합니다.

## 키 유형

| 유형             | 동작 주체                        | 생성, 조회 및 폐기할 수 있는 사용자                               | 사용 시 권한                                                                             |
| ---------------- | -------------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 개인 키          | 하나의 테넌트 내에서 사용자 본인 | 본인만 가능하며, 해당 테넌트의 현재 구성원인 동안에만 가능합니다. | 키에 부여된 권한과 현재 테넌트 권한을 모두 적용합니다. 양쪽 모두 호출을 허용해야 합니다. |
| 테넌트 서비스 키 | 특정 사용자와 독립적인 테넌트    | 해당 테넌트의 현재 Owner 또는 Admin.                              | 키에 부여된 권한만 적용합니다. 생성한 사용자가 탈퇴해도 계속 작동합니다.                 |

- Owner와 Admin을 포함한 다른 사용자는 개인 키를 보거나 폐기할 수 없습니다. Billing 및 Member 역할은 테넌트 서비스 키를 관리할 수 없습니다.
- 머신 간 통신용 ID는 키를 관리할 수 없습니다. 키는 Delcore 자체의 인증 정보로는 사용할 수 없으며, 권한이 부여된 서비스에서만 사용할 수 있습니다.
- 두 유형 모두 하나의 테넌트에 연결됩니다. 다른 테넌트에서는 키를 사용할 수 없습니다.

## 키 생성

Delino 로그인 토큰을 사용하여 `https://delcore.api.delino.io`에서 `delcore.v1.DelcoreService/CreateApiKey`를 호출하세요.

| 필드         | 규칙                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requestKey` | 직접 생성한 UUID v7입니다. 동일한 키와 입력으로 요청을 반복하면 기존 결과가 반환됩니다.                                                                                     |
| `tenantId`   | 키가 속한 테넌트입니다.                                                                                                                                                     |
| `ownerKind`  | `API_KEY_OWNER_KIND_PERSONAL` 또는 `API_KEY_OWNER_KIND_TENANT`입니다.                                                                                                       |
| `name`       | 1~100바이트이며, 공백으로만 이루어져서는 안 되고 제어 문자를 포함할 수 없습니다.                                                                                            |
| `grants`     | 1~16개의 권한 부여 항목입니다. 각 항목에는 `serviceId`와 각각 최대 100바이트인 `capabilities` 1~32개가 있습니다. 서비스는 한 번만 나타나야 하며, 기능은 중복될 수 없습니다. |
| `expiresAt`  | 선택 사항인 미래의 RFC 3339 시간입니다. 지정하지 않으면 폐기할 때까지 키가 유효합니다.                                                                                      |

Delcore 카탈로그(`GetCatalog`)에서 서비스의 `serviceId`와 기능을 확인하세요. DeliTools의 경우 필요한 `translate` 및 `extract` 기능에 대한 권한을 부여하세요. Delcore는 서비스가 선언한 기능만 허용하므로, 기능 이름에 오타가 있으면 키 생성 시 거부됩니다.

```sh
curl --request POST "https://delcore.api.delino.io/delcore.v1.DelcoreService/CreateApiKey" \
  --header "Content-Type: application/json" \
  --header "Authorization: Bearer $DELINO_TOKEN" \
  --data '{"requestKey":"<uuid-v7>","tenantId":"<tenant-id>","ownerKind":"API_KEY_OWNER_KIND_TENANT","name":"Production translation","grants":[{"serviceId":"<deli-tools-service-id>","capabilities":["translate"]}]}'
```

이 예시에서는 만료 시간을 설정하지 않으므로 폐기할 때까지 키가 유효합니다. 만료 시간을 추가하려면 `expiresAt`을 미래의 RFC 3339 시간으로 설정하세요.

응답에는 키 세부 정보와 `dlk_`로 시작하는 `secret`이 포함됩니다.

- **시크릿은 한 번만 표시됩니다.** 지금 시크릿 관리자에 복사해 두세요. Delcore는 해시만 보관하며, 목록이나 반복 요청의 응답에는 시크릿을 표시하지 않습니다.
- **시크릿 분실.** 시크릿을 분실했거나 반복 요청의 응답에서 `secret`이 비어 있다면, 새 키를 생성하고 기존 키를 폐기하세요.
- **비밀번호처럼 취급하세요.** 서버 측 코드에서만 사용하고 로그, 저장소 및 프런트엔드 번들에 포함하지 마세요.
- 제한: 사용자와 테넌트의 각 조합당 활성 개인 키를 100개까지, 테넌트당 활성 테넌트 키를 100개까지 보유할 수 있습니다. 폐기되거나 만료된 키는 활성 키로 집계되지 않지만 30일 동안 보관됩니다. 하나의 범위에는 상태에 관계없이 최대 500개의 키를 보관할 수 있습니다.

부여된 권한과 만료 시간은 키를 생성할 때 고정됩니다. 수정, 갱신 또는 교체를 위한 호출은 없습니다. 키를 변경하려면 새 권한이나 만료 시간으로 대체 키를 생성하고, 애플리케이션이 해당 키를 사용하도록 전환한 다음 기존 키를 폐기하세요.

## 키 조회 및 폐기

- `ListApiKeys`는 `tenantId`와 `ownerKind`를 받습니다. 폐기되거나 만료된 키를 포함한 키 세부 정보를 반환하며, 시크릿은 절대 반환하지 않습니다. 개인 키 목록에는 본인의 키만 표시됩니다. 테넌트 키 목록을 조회하려면 Owner 또는 Admin 역할이 필요합니다. 더 조회하려면 반환된 `nextAfterId`를 `page.afterId`에 사용하세요.
- `RevokeApiKey`는 `requestKey`, `tenantId` 및 `keyId`를 받습니다. 새 요청에 즉시 적용됩니다. 다시 폐기해도 안전합니다.

## 키 사용

키에 권한이 부여된 서비스에 시크릿을 `Authorization: Bearer dlk_...`로 전송하세요. DeliTools에서는 [API 참조](/ko/services/delitools/api-reference)에 설명된 대로 `Translate` 및 `Extract`에 사용할 수 있습니다.

- 키를 사용할 때 `tenantId`는 선택 사항입니다. 전송한다면 키의 테넌트와 일치해야 합니다.
- 키는 해당 서비스에 대해 부여한 기능만 사용할 수 있습니다. 한 서비스용 키는 다른 서비스에서 사용할 수 없습니다.
- Delcore는 모든 요청에서 키를 확인하며, 각 AI 재시도 전에도 다시 확인합니다. 폐기, 만료, 권한 상실 또는 결제 이용 권한 상실 시 새 요청과 추가 재시도가 중단됩니다. 이미 실행 중인 제공업체 호출은 완료될 수 있습니다.
- 테넌트에서 제거되거나 그룹 권한을 상실하는 등 테넌트 내에서 해당 기능을 더 이상 사용할 수 없는 동안에는 개인 키가 작동하지 않습니다. 사용자가 제거되어도 키는 삭제되지 않습니다.
- 테넌트 키는 생성자의 구성원 자격에 의존하지 않습니다.
- 키를 사용한 호출은 로그인 토큰을 사용한 호출과 동일한 요금으로 키의 테넌트에 청구됩니다. [결제](/ko/services/delitools/billing)를 참조하세요.
- 테넌트를 삭제하면 삭제가 최종 확정될 때 Delcore가 해당 테넌트의 키를 삭제합니다. 개인 키는 사용자의 탈퇴가 승인되는 즉시 삭제됩니다. 삭제된 테넌트의 키는 유효하지 않습니다.

## 일반적인 오류

| 상황                                                              | 결과                                                                |
| ----------------------------------------------------------------- | ------------------------------------------------------------------- |
| 시크릿에 오타가 있거나, 알 수 없거나, 폐기되었거나, 만료됨        | `unauthenticated`. Delcore는 이 중 어떤 경우인지 알려주지 않습니다. |
| 키에 서비스 또는 기능 권한이 없음                                 | `permission_denied`                                                 |
| `tenantId`가 키의 테넌트와 일치하지 않음                          | `permission_denied`                                                 |
| 사용자의 역할로 이 키 유형을 관리할 수 없음                       | 생성, 조회 또는 폐기 시 Delcore가 `permission_denied`를 반환합니다. |
| 다른 사용자의 개인 키 또는 알 수 없는 키를 폐기함                 | Delcore가 `not_found`를 반환합니다.                                 |
| 삭제 중인 테넌트에서 키를 생성하거나 키 한도를 초과하여 생성함    | Delcore가 `failed_precondition`을 반환합니다.                       |
| 권한 부여 항목, 이름, 서비스, 기능 또는 만료 시간이 유효하지 않음 | 키 생성 시 Delcore가 `invalid_argument`를 반환합니다.               |
| 테넌트 결제가 차단됨                                              | DeliTools가 `ERROR_REASON_BILLING_BLOCKED`를 반환합니다.            |
