# DeliTools API 키

API 키를 사용하면 서버에서 Delino 로그인 토큰 없이 DeliTools를 호출할 수 있습니다. Delcore는 모든 Delino 서비스의 키를 생성하고 검증하므로, 동일한 키 기능을 다른 서비스에서도 사용할 수 있습니다. 키는 Delino 로그인 토큰으로 관리하며, 서비스를 호출할 때는 키를 Bearer 토큰으로 사용합니다.

## 키 유형

| 유형             | 동작 주체                   | 생성, 조회 및 폐기할 수 있는 사람                               | 사용 시 권한                                                       |
| ---------------- | --------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------ |
| 개인 키          | 한 테넌트 내의 사용자 본인  | 본인만 가능하며, 해당 테넌트의 현재 멤버인 동안에만 가능합니다. | 키에 부여된 권한과 현재 테넌트 권한이 모두 호출을 허용해야 합니다. |
| 테넌트 서비스 키 | 사용자와 무관한 테넌트 자체 | 해당 테넌트의 현재 Owner 또는 Admin.                            | 키에 부여된 권한만 적용됩니다. 생성자가 탈퇴해도 계속 작동합니다.  |

- Owner와 Admin을 포함한 다른 사용자는 개인 키를 조회하거나 폐기할 수 없습니다. Billing 및 Member 역할은 테넌트 서비스 키를 관리할 수 없습니다.
- 머신 간 통신용 ID는 키를 관리할 수 없습니다. 키는 Delcore 자체의 자격 증명으로 사용할 수 없으며, 권한이 부여된 서비스에서만 사용할 수 있습니다.
- 두 유형 모두 하나의 테넌트에 연결됩니다. 키를 다른 테넌트에서 사용할 수 없습니다.

## 키 생성

Delino 로그인 토큰으로 `https://delcore.api.delino.io`의 `delcore.v1.DelcoreService/CreateApiKey`를 호출합니다.

| 필드         | 규칙                                                                                                                                                                          |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requestKey` | 직접 생성한 UUID v7입니다. 동일한 키와 입력으로 요청을 반복하면 기존 결과가 다시 반환됩니다.                                                                                  |
| `tenantId`   | 키가 속한 테넌트입니다.                                                                                                                                                       |
| `ownerKind`  | `API_KEY_OWNER_KIND_PERSONAL` 또는 `API_KEY_OWNER_KIND_TENANT`입니다.                                                                                                         |
| `name`       | 1~100바이트이며, 공백으로만 이루어져서는 안 되고 제어 문자를 포함할 수 없습니다.                                                                                              |
| `grants`     | 1~16개의 권한 부여 항목입니다. 각 항목에는 `serviceId`와 각각 최대 100바이트인 1~32개의 `capabilities`가 있습니다. 서비스는 한 번만 나타나야 하며, 기능은 중복될 수 없습니다. |
| `expiresAt`  | 선택 사항인 미래의 RFC 3339 시각입니다. 지정하지 않으면 폐기할 때까지 키가 유효합니다.                                                                                        |

서비스의 `serviceId`와 기능은 Delcore 카탈로그(`GetCatalog`)에서 확인할 수 있습니다. DeliTools의 경우 필요한 `translate` 및 `extract` 기능의 권한을 부여하세요. Delcore는 서비스가 선언한 기능만 허용하므로, 기능 이름에 오타가 있으면 키 생성 시 거부됩니다.

```sh
curl --request POST "https://delcore.api.delino.io/delcore.v1.DelcoreService/CreateApiKey" \
  --header "Content-Type: application/json" \
  --header "Authorization: Bearer $DELINO_TOKEN" \
  --data '{"requestKey":"<uuid-v7>","tenantId":"<tenant-id>","ownerKind":"API_KEY_OWNER_KIND_TENANT","name":"Production translation","grants":[{"serviceId":"<deli-tools-service-id>","capabilities":["translate"]}],"expiresAt":"2027-01-01T00:00:00Z"}'
```

응답에는 키 세부 정보와 `dlk_`로 시작하는 `secret`이 포함됩니다.

- **비밀 값은 한 번만 표시됩니다.** 지금 비밀 관리 도구에 복사해 두세요. Delcore는 해시만 보관하며, 목록이나 반복 요청의 응답에 비밀 값을 표시하지 않습니다.
- **비밀 값 분실.** 비밀 값을 잃어버렸거나 반복 요청의 응답에서 `secret`이 비어 있다면 새 키를 생성하고 기존 키를 폐기하세요.
- **비밀번호처럼 취급하세요.** 서버 측 코드에서만 사용하고 로그, 저장소 및 프런트엔드 번들에 포함하지 마세요.
- 각 테넌트에서 보유할 수 있는 활성 키 수에는 제한이 있습니다. 사용자별 개인 키는 20개, 테넌트 키는 총 20개입니다. 폐기되거나 만료된 키는 이 수에 포함되지 않습니다.

부여된 권한과 만료 시각은 키 생성 시 고정됩니다. 수정, 갱신 또는 교체를 위한 호출은 없습니다. 키를 변경하려면 새로운 권한이나 만료 시각으로 대체 키를 생성하고, 애플리케이션에서 해당 키를 사용하도록 전환한 다음 기존 키를 폐기하세요.

## 키 조회 및 폐기

- `ListApiKeys`는 `tenantId`와 `ownerKind`를 받습니다. 폐기되거나 만료된 키를 포함한 키 세부 정보를 반환하며, 비밀 값은 절대 반환하지 않습니다. 개인 키 목록에는 본인의 키만 표시됩니다. 테넌트 키 목록을 조회하려면 Owner 또는 Admin 역할이 필요합니다. 더 조회하려면 반환된 `nextAfterId`를 `page.afterId`에 사용하세요.
- `RevokeApiKey`는 `requestKey`, `tenantId`, `keyId`를 받습니다. 폐기는 새 요청에 즉시 적용됩니다. 다시 폐기해도 안전합니다.

## 키 사용

키에 권한이 부여된 서비스에 비밀 값을 `Authorization: Bearer dlk_...`로 전송합니다. DeliTools에서는 [API 참조](/ko/services/delitools/api-reference)에 설명된 대로 `Translate`와 `Extract`에 사용할 수 있습니다.

- 키를 사용할 때 `tenantId`는 선택 사항입니다. 전송한다면 키의 테넌트와 일치해야 합니다.
- 키는 해당 서비스에 대해 부여된 기능만 사용할 수 있습니다. 한 서비스용 키는 다른 서비스에서 사용할 수 없습니다.
- Delcore는 모든 요청 시, 그리고 각 AI 재시도 전에 키를 다시 확인합니다. 폐기, 만료, 권한 또는 결제 접근 권한 상실 시 새 요청과 추가 재시도가 중단됩니다. 이미 실행 중인 제공업체 호출은 완료될 수 있습니다.
- 개인 키는 테넌트에서 해당 기능을 사용할 권한이 없는 동안 작동하지 않습니다. 예를 들어 테넌트에서 제거되거나 그룹 권한을 잃은 경우가 이에 해당합니다. 사용자가 제거되어도 키는 삭제되지 않습니다.
- 테넌트 키는 생성자의 멤버십에 의존하지 않습니다.
- 키를 사용한 호출은 로그인 토큰을 사용한 호출과 동일한 요금으로 키의 테넌트에 청구됩니다. [요금 청구](/ko/services/delitools/billing)를 참조하세요.
- 테넌트를 삭제하면 삭제가 최종 확정될 때 Delcore가 해당 키를 삭제합니다. 개인 키는 사용자의 탈퇴가 수락되는 즉시 삭제됩니다. 삭제된 테넌트의 키는 유효하지 않습니다.

## 일반적인 오류

| 상황                                                              | 결과                                                                |
| ----------------------------------------------------------------- | ------------------------------------------------------------------- |
| 비밀 값에 오타가 있거나, 알 수 없거나, 폐기되었거나, 만료됨       | `unauthenticated`. Delcore는 이 중 어떤 경우인지 알리지 않습니다.   |
| 키에 서비스 또는 기능 권한이 없음                                 | `permission_denied`                                                 |
| `tenantId`가 키의 테넌트와 일치하지 않음                          | `permission_denied`                                                 |
| 사용자의 역할로 이 키 유형을 관리할 수 없음                       | 생성, 조회 또는 폐기 시 Delcore가 `permission_denied`를 반환합니다. |
| 다른 사용자의 개인 키 또는 알 수 없는 키를 폐기함                 | Delcore가 `not_found`를 반환합니다.                                 |
| 삭제 중인 테넌트에서 키를 생성하거나 키 수 제한을 초과하여 생성함 | Delcore가 `failed_precondition`을 반환합니다.                       |
| 권한 부여 항목, 이름, 서비스, 기능 또는 만료 시각이 잘못됨        | 키 생성 시 Delcore가 `invalid_argument`를 반환합니다.               |
| 테넌트의 결제가 차단됨                                            | DeliTools가 `ERROR_REASON_BILLING_BLOCKED`를 반환합니다.            |
