# Delcore

Delcore는 Delino 서비스에 공유 테넌트, 접근 제어 및 청구 기능을 제공합니다. 공식 API 서버는 `https://delcore.api.delino.io`입니다. 이 페이지에서는 서비스 개발자를 위해 API 키 검증, 사용량 요금, 레코드 만료 및 테넌트 상태 확인을 설명합니다.

## 테넌트 상태 확인

등록된 서비스는 Delcore에 테넌트가 활성, 차단 또는 삭제 상태인지 확인할 수 있습니다. 서비스가 테넌트의 데이터를 저장하지만 각 요청에 Delino 사용자가 연결되어 있지 않은 경우(예: 프로젝트 API 키로 호출하는 경우)에 이 확인 기능을 사용하세요.

테넌트 ID 1~100개로 `delcore.v1.DelcoreService/GetTenantStates`를 호출하세요. 각 ID는 소문자 UUID 버전 7이어야 합니다. 서비스의 Logto 머신 간 애플리케이션 액세스 토큰으로 인증하세요. 서비스는 Delcore에 등록되어 있어야 하며 `authorize` 범위가 있어야 합니다. 사용자 토큰, 등록되지 않은 서비스, 이 범위가 없는 서비스는 테넌트 상태를 읽을 수 없습니다.

응답에는 요청한 각 테넌트 ID가 전송한 순서대로 다음 상태 중 하나와 함께 반환됩니다.

| 상태                    | 의미                                             |
| ----------------------- | ------------------------------------------------ |
| `TENANT_STATE_ACTIVE`   | 테넌트가 존재하며 차단되거나 삭제 중이 아닙니다. |
| `TENANT_STATE_BLOCKED`  | 플랫폼 운영자가 테넌트를 차단했습니다.           |
| `TENANT_STATE_DELETING` | 삭제가 대기 중입니다.                            |
| `TENANT_STATE_DELETED`  | 삭제가 확정되었습니다.                           |
| `TENANT_STATE_UNKNOWN`  | Delcore에 이 ID의 테넌트가 없습니다.             |

둘 이상의 조건이 적용되면 `DELETED`가 `DELETING`보다, `DELETING`이 `BLOCKED`보다, `BLOCKED`가 `ACTIVE`보다 우선합니다.

상태는 청구와 무관합니다. 구독 만료, 갱신 실패, 분쟁 또는 잔액 부족으로 테넌트가 `BLOCKED` 상태가 되지는 않습니다. 사용자가 유료 작업을 실행할 수 있는지 판단하려면 대신 `Authorize`를 사용하세요. 이 확인 기능은 데이터를 읽기만 합니다. 테넌트를 변경하거나, 유료 사용을 승인하거나, 결제 제공업체에 연락하지 않으며 테넌트 이름, 사용자 세부 정보 또는 청구 정보를 반환하지 않습니다.

## 결과 및 실패 처리

- `TENANT_STATE_ACTIVE`인 경우에만 접근을 허용하세요. 단, 소유자 또는 관리자에 대해 자체적으로 문서화한 규칙이 차단되거나 삭제 중인 테넌트에 대한 접근을 허용하는 경우는 예외입니다.
- `TENANT_STATE_UNKNOWN`, 요청 오류, 시간 초과 및 Delcore 사용 불가 상태는 접근 불가로 처리하세요. 이러한 경우에는 데이터를 삭제하지 마세요.
- 테넌트 삭제에 따른 정리 작업에서는 명시적인 `TENANT_STATE_DELETED`를 받은 후에만 보관 중인 테넌트 데이터를 자동으로 삭제하세요. `BLOCKED`와 `DELETING`은 이러한 정리를 절대 허용하지 않습니다. 고정된 레코드 만료 기간은 테넌트 상태와 무관하게 적용됩니다.
- 유효하지 않은 ID, 빈 요청 또는 100개를 초과하는 ID는 잘못된 인수 오류를 반환합니다. 자격 증명이 누락되었거나 만료되었거나 유효하지 않으면 인증되지 않음 오류를 반환합니다. 테넌트 상태를 읽을 권한이 없는 호출자는 권한 거부 오류를 받습니다. 그 밖의 실패는 상관관계 ID가 포함된 오류를 반환합니다. 지원을 요청할 때 오류 세부 정보와 `X-Delcore-Correlation-Id` 헤더에 있는 이 ID를 포함하세요.
- 실패한 요청은 나중에 다시 시도하세요. 요청 실패는 테넌트가 활성 상태이거나 삭제되었음을 의미하지 않습니다.

## 사용량 요금 및 레코드 만료

사용량 단가는 기존 구독자를 포함한 모든 고객에게 최초 실행 시작 시점을 기준으로 적용됩니다. 해당 시작 시점을 `IngestEvent`의 `occurred_at`으로 보고하고, 실행 재시도 및 사용량 대사 중에도 유지하세요. 가격 변경은 이후 실행에 적용되며, 지연 전달과 정정에는 원래 가격 적용 기준이 유지됩니다. 정기 결제 요금, 선택한 기능 및 포함 사용량 부여분에는 해당 구독 조건이 유지됩니다.

요청 중복 제거는 레코드가 처음 생성된 시점부터 30일간 유지됩니다. 재시도로 이 기간이 연장되지는 않습니다. 만료 후에는 동일한 요청 키로 새 작업을 시작할 수 있으며, 이때 현재 권한과 별도의 결제 또는 이벤트 식별 확인이 적용됩니다. 수락된 사용량 이벤트는 중복 회계 반영을 방지하기 위해 영구적인 식별 정보를 유지합니다.

소비자 서비스는 실행 또는 사용량을 여전히 알 수 없거나 보고가 Delcore에 도달하지 않았더라도 사용량 전달 및 대사 레코드를 최초 생성 후 30일이 지나면 삭제해야 합니다. 만료 시점까지 전달 재시도와 알 수 없는 사용량 조회를 계속한 다음, 보류 중인 청구를 포기하세요. 청구를 위해 사용량을 추정하지 마세요. 이로 인해 청구 가능한 사용량이 영구적으로 유실될 수 있으며, 만료된 실행 중복 제거 키로 새 실행과 청구가 허용될 수 있습니다. 플랫폼 감사 레코드와 운영 로그도 생성 후 30일이 지나면 만료됩니다. 이러한 제한은 Delcore가 이미 수락한 회계 항목을 삭제하거나 API 키의 유효성을 변경하지 않습니다.

## API 키 검증

Delcore는 등록된 모든 서비스에 대해 재사용 가능한 개인 및 테넌트 서비스 API 키를 발급합니다. 사용자와 테넌트 소유자 및 관리자는 Delino 로그인 토큰으로 키를 생성합니다. 사용자 관점의 절차는 [DeliTools API 키](/ko/services/delitools/api-keys)를 참고하세요. 키는 `dlk_`로 시작하고, 선택한 서비스의 선택한 기능에 대한 권한을 부여하며, 하나의 테넌트에 속합니다.

등록된 서비스는 호출자로부터 받은 키를 `delcore.v1.DelcoreService/AuthorizeApiKey`로 검증합니다. 서비스의 Logto 머신 간 액세스 토큰으로 인증하세요. 서비스는 등록되어 있어야 하며 `authorize` 범위가 있어야 합니다.

- 전체 `secret`, 사용 중인 `capability`, 유료 작업의 경우 `paid`를 전송하세요. `Authorize`에서와 마찬가지로 `feature_key`와 `group_values`도 전송할 수 있습니다.
- Delcore는 호출 서비스를 명시한 권한 부여만 평가하므로, 서비스가 다른 서비스의 기능을 승인할 수는 없습니다.
- 형식이 잘못되었거나, 알 수 없거나, 폐기되었거나, 만료된 시크릿 또는 삭제된 테넌트의 시크릿은 인증되지 않음 오류를 반환하며 키 세부 정보는 반환하지 않습니다. 서비스 자체 토큰이 거부된 경우에도 Delcore는 같은 방식으로 응답하므로, 유효한 모든 키가 실패한다면 서비스 자격 증명을 확인하세요. 이를 유효하지 않은 자격 증명으로 처리하세요.
- 유효한 시크릿의 경우 응답에는 `allowed`, `reasons`, 선택적인 `feature`와 함께 `keyId`, `tenantId`, `ownerKind`, `userId`가 포함됩니다. 해당 기능에 대한 권한이 없는 키는 `BLOCK_REASON_PERMISSION`과 함께 `allowed: false`를 반환합니다.
- 개인 키에는 해당 테넌트에서 해당 기능에 대한 사용자의 현재 권한도 필요합니다. 테넌트 키는 키를 생성한 사용자와 무관합니다. 두 키 모두 활성 테넌트가 필요하며, `paid`가 설정된 경우 `Authorize`와 동일한 청구 확인이 필요합니다.
- 호출자가 테넌트를 제공한 경우 반환된 `tenantId`와 비교하고, 일치하지 않으면 거부하세요.
- 모든 요청을 확인하세요. 결과를 캐시하지 마세요. 오류, 시간 초과 및 Delcore 사용 불가 상태는 새로운 유료 작업에 대해 접근 불가로 처리하세요. 승인 결과는 아무것도 예약하지 않습니다.
