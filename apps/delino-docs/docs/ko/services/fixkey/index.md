# FixKey

FixKey는 잘못된 키보드 배열로 입력한 단어를 교정합니다. 한국어 두벌식과 미국 영어 QWERTY 사이의 양방향 교정을 지원합니다. FixKey는 데스크톱에서 로컬로 실행되며 계정이 필요하지 않습니다.

## FixKey 설치

[FixKey 릴리스](https://github.com/delinoio/apps/releases?q=fixkey%40)를 열고 운영체제와 프로세서에 맞는 패키지를 선택하세요.

- macOS ARM64: Apple silicon용 DMG입니다. FixKey를 응용 프로그램 폴더로 옮긴 뒤 실행하세요.
- Windows x64 또는 ARM64: 프로세서에 맞는 EXE 설치 프로그램입니다. Windows 패키지에는 Authenticode 게시자 서명이 없으므로 Windows에서 알 수 없는 게시자 또는 SmartScreen 경고가 표시될 수 있습니다.
- Linux X11 x64 또는 ARM64: 프로세서에 맞는 AppImage입니다. Wayland는 지원하지 않습니다.

최소 실행 요구사항은 Apple silicon의 macOS 11, WebView2가 설치된 Windows 10, 또는 X11, GTK 3, WebKitGTK 4.1과 AT-SPI 접근성 버스를 갖춘 Linux입니다. 이는 플랫폼 실행 조건이며, 모든 애플리케이션이나 텍스트 필드와의 호환성을 보장하지 않습니다.

## 권한 허용

FixKey가 편집 가능한 필드에서 현재 단어를 읽고 바꾸려면 운영체제의 접근성 및 입력 권한이 필요합니다. 권한 대화상자의 안내에 따라 시스템 설정에서 요청된 권한을 허용한 뒤 **다시 확인**을 선택하세요. 필요한 권한과 내장 사전이 준비될 때까지 교정은 비활성 상태를 유지합니다. 비밀번호 및 보호된 필드는 제외됩니다.

macOS에서는 시스템 설정의 **손쉬운 사용**과 **입력 모니터링**을 확인하세요. 손쉬운 사용 권한으로 별도의 입력 모니터링 항목 없이도 실질적인 입력 접근 권한이 부여될 수 있습니다. 목록을 확인하려면 FixKey의 **일반**에서 **입력 모니터링 설정**을 선택하세요. FixKey가 없다면 시스템 권한 목록의 **+**를 사용해 응용 프로그램 폴더의 현재 FixKey.app을 추가한 뒤, FixKey로 돌아와 다시 확인하세요. macOS가 이미 실질적인 입력 접근 권한을 부여했다면 별도의 목록 항목은 필요하지 않습니다.

## 단어 교정

기본적으로 두 배열 모두 활성화되어 있습니다. 편집 가능한 필드에 입력하고 공백이나 문장부호로 단어를 마치세요. FixKey는 활성화된 배열의 후보를 내장 사전으로 검사합니다. 활성화된 언어 중 정확히 하나만 해당 후보를 인식하고, 그 후보가 원문과 다를 때만 단어를 바꿉니다. 어느 언어도 후보를 인식하지 못하거나 둘 이상의 언어가 후보를 인식하면 단어를 그대로 둡니다.

예를 들어 키 입력 `rPthrgo`와 `zlqhemrk`는 `계속해`와 `키보드가`로 바뀔 수 있습니다. 이는 배열 교정의 예시이며, 결과는 현재 필드, 입력 문맥, 사전 인식 여부에 따라 달라집니다.

FixKey는 교정된 단어 뒤의 구분 문자를 유지합니다. Enter와 Tab은 교정을 시작하지 않습니다. URL이나 이메일 주소에 쓰이는 문장부호는 FixKey가 전체 토큰을 분류할 수 있을 때까지 평가를 지연시킬 수 있습니다. 글자 사이의 아포스트로피와 하이픈은 단어 내부에 유지됩니다.

자동 교정은 붙여넣거나 프로그램이 삽입한 텍스트, 숫자, 이모지, URL, 이메일 주소와 여러 문자 체계가 섞인 토큰을 건너뜁니다. 한국어 입력 조합이 끝날 때까지 기다립니다. 알 수 없는 필드, 권한이 없는 필드, 안전하게 변경할 수 없는 필드는 수정하지 않습니다.

macOS 또는 Windows에서 자동 교정에 성공하면 FixKey는 교정된 언어에 맞는 활성 입력 소스도 선택하려고 시도합니다. Windows에서는 별도의 미국 영어 QWERTY 입력 소스가 활성화되어 있지 않아도 Microsoft 한국어 IME의 한글 모드와 영문 모드를 사용할 수 있습니다. 한국어 IME는 두벌식으로 설정해 두세요. 입력 소스를 선택할 수 없거나 선택에 실패해도 교정된 텍스트와 즉시 되돌리기는 유지됩니다. Windows에서 닫혀 있거나 지원되지 않는 IME의 모드는 변경하지 않습니다. Linux에서는 현재 입력 소스를 유지합니다. 즉시 되돌리기는 입력 소스를 다시 변경하지 않습니다.

### 교정 되돌리기

자동 교정 직후 Backspace를 누르면 원래 단어와 구분 문자를 복원합니다. 이후 Backspace는 평소처럼 삭제합니다. 커서를 이동하거나, 선택 영역을 바꾸거나, 다른 필드로 전환하거나, 다음 단어를 입력하기 시작하면 즉시 되돌릴 수 있는 문맥이 끝납니다.

### 후보 직접 선택

1. **단축키**를 열고 수동 후보 단축키를 지정하세요. 기본적으로 지정되어 있지 않습니다. 등록에 실패하면 표시된 이유를 확인하거나 다른 단축키를 선택하세요.
2. 편집 가능한 필드에 단어를 입력하고 단축키를 누르세요.
3. 방향키로 후보를 선택하세요. Enter로 적용하거나 Esc로 선택 창을 닫으세요.

후보 선택 창에는 사전 인식 결과가 표시됩니다. 인식되지 않은 후보도 직접 선택할 수 있습니다. 원본 필드의 커서를 이동하거나 다른 애플리케이션으로 전환하면 선택 창이 닫힙니다. FixKey가 안전한 교체 대상을 확인할 수 없으면 선택 창을 사용할 수 없습니다.

## 교정 설정

**일반**에서 교정을 일시 중지하거나 재개하고, 사용할 언어를 선택하고, 로그인 시 자동 실행을 켜고, 인터페이스 언어와 테마를 선택할 수 있습니다. 로그인 시 자동 실행은 기본적으로 꺼져 있습니다. 설정은 즉시 적용되며 로컬에 저장됩니다.

애플리케이션을 교정하지 않으려면 **제외 앱**에서 추가하세요. 제외 설정은 표시 이름만이 아니라 애플리케이션의 식별 정보를 사용합니다. 식별 정보를 확인할 수 없는 애플리케이션도 목록에 남아 검토할 수 있습니다.

## 개인정보와 오프라인 사용

FixKey는 기기에서 입력을 처리합니다. 입력 텍스트, 후보, 문서 내용, 창 제목이나 교정 기록을 저장하거나 전송하지 않습니다. 교체에 클립보드를 사용하지 않습니다. 사용 현황 수집, 원격 충돌 보고나 자동 진단 업로드도 없습니다.

사전이 내장되어 있으므로 권한이 준비되면 첫 실행부터 오프라인으로 교정할 수 있습니다. 사전은 애플리케이션 업데이트와 함께 변경되며, 별도의 사전 다운로드나 사용자 사전 편집기는 없습니다. 네트워크는 업데이트 확인과 다운로드에만 사용됩니다.

## FixKey 업데이트

FixKey는 시작할 때, 실행 중 24시간마다, 그리고 **업데이트**에서 확인을 요청할 때 안정 버전 업데이트를 확인합니다. 다운로드와 설치에는 사용자 동의가 필요합니다. 업데이트 파일의 서명을 검증하며, 서명이 유효하지 않으면 설치하지 않습니다. 설치 전에 교정을 중지하고 설정을 보존합니다.

확인에 실패하면 수동으로 다시 시도하거나 다음 예약 확인을 기다리세요. 설치에 실패하면 FixKey를 다시 시작하거나 FixKey 릴리스에서 적절한 패키지를 받아 다시 설치하세요. 이전 릴리스를 수동으로 다시 설치할 수 있으며, FixKey는 자동으로 이전 버전으로 되돌리지 않습니다.

## 문제 해결과 지원

교정이 비활성 상태라면 **진단 및 도움말**을 열고 상태와 이유 코드를 확인하세요. 권한을 다시 확인하고 다른 애플리케이션의 편집 가능한 필드에서 시도하세요. 편집 가능한 필드를 기다리는 상태는 현재 필드를 안전하게 식별할 수 없다는 뜻입니다. 교정이 일시 중지되었는지, 해당 애플리케이션이 제외되었는지도 확인하세요.

**로그 폴더 열기**로 로컬 진단 로그를 확인하거나 **로그 삭제**로 제거하세요. 로그에는 입력 내용 대신 진단 결과와 이유 코드가 담깁니다. FixKey는 최대 7일, 총 10 MiB까지 로그를 보관합니다.

도움이 필요하면 **진단 및 도움말**의 GitHub Issues 링크를 이용하거나 [GitHub Issues](https://github.com/delinoio/apps/issues)를 여세요. FixKey 버전, 운영체제, 영향을 받는 애플리케이션과 이유 코드를 포함하세요. 개인적인 텍스트나 자격 증명은 포함하지 마세요.
