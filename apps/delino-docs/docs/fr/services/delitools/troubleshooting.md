# Configuration et dépannage de DeliTools

Cette page vous aide à configurer un client pour DeliTools et à corriger les erreurs. Pour les règles relatives aux champs, consultez la [référence de l’API](/fr/services/delitools/api-reference).

## Configurer votre client

- **URL de base.** Utilisez l’URL du serveur de l’API DeliTools fournie par votre opérateur de service. Les procédures sont accessibles à `/delitools.v1.DelitoolsService/Translate` et `/delitools.v1.DelitoolsService/Extract`.
- **Protocole.** Utilisez un client Connect, ou envoyez du JSON avec `POST` et `Content-Type: application/json`. Les noms des champs JSON utilisent la notation lowerCamelCase.
- **Identifiant d’authentification.** Envoyez `Authorization: Bearer <credential>`. Utilisez un jeton de connexion Delino ou une clé API commençant par `dlk_`. Conservez les clés dans le code côté serveur. DeliTools ne prend pas en charge les appels depuis les navigateurs.
- **Locataire.** Un jeton de connexion nécessite `tenantId`. Une clé API identifie déjà son locataire ; si vous envoyez également `tenantId`, il doit correspondre.
- **Modèle.** Utilisez un identifiant de modèle autorisé par l’opérateur. L’extraction utilise un modèle fixe et ne comporte pas de champ `model`.
- **Délais d’expiration.** Définissez un délai d’expiration du client adapté à votre requête la plus volumineuse. Un appel au fournisseur peut prendre plusieurs secondes, et DeliTools peut réessayer en cas d’échecs transitoires ; l’appel complet peut donc durer plus longtemps. Une requête qui dépasse le délai d’exécution défini par l’opérateur renvoie `ERROR_REASON_TIMEOUT` ; si votre propre délai d’expiration met fin à l’appel en premier, DeliTools le traite comme une annulation.
- **Nouvelles tentatives.** Réessayez en cas de `ERROR_REASON_RATE_LIMITED`, `ERROR_REASON_DEPENDENCY_UNAVAILABLE` et `ERROR_REASON_TIMEOUT`, ainsi qu’en cas de `ERROR_REASON_PROVIDER_FAILED` uniquement lorsque le code Connect est `unavailable`, avec un délai d’attente exponentiel et un court délai aléatoire. Chaque nouvelle tentative constitue une nouvelle exécution susceptible d’être facturée. Consultez la [facturation](/fr/services/delitools/billing). Ne réessayez pas sans modification les requêtes qui échouent à la validation.

## Corriger une erreur

| Motif                                 | Marche à suivre                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ERROR_REASON_INVALID_INPUT`          | Corrigez la requête. Vérifiez les chaînes vides, les balises de langue, l’identifiant du locataire, le modèle et si le schéma est un JSON valide.                                                                                                                                                                                                                 |
| `ERROR_REASON_UNAUTHENTICATED`        | Vérifiez le jeton ou la clé. Il peut s’agir d’une erreur de saisie, d’une expiration, d’une révocation ou d’un locataire supprimé. Créez une nouvelle clé si vous avez perdu le secret. Si toutes les clés valides échouent soudainement, signalez-le à l’opérateur du service : une identité de service mal configurée fait apparaître les clés comme invalides. |
| `ERROR_REASON_PERMISSION_DENIED`      | Vérifiez que la clé accorde `translate` ou `extract`, que l’utilisateur dispose toujours des autorisations dans le locataire et que tout `tenantId` envoyé correspond au locataire de la clé.                                                                                                                                                                     |
| `ERROR_REASON_BILLING_BLOCKED`        | Résolvez le problème de facturation dans Delcore, par exemple le solde ou le renouvellement, puis réessayez.                                                                                                                                                                                                                                                      |
| `ERROR_REASON_LIMIT_EXCEEDED`         | Envoyez moins de données : moins d’éléments, un texte plus court ou un schéma plus petit. Répartissez les tâches volumineuses sur plusieurs requêtes.                                                                                                                                                                                                             |
| `ERROR_REASON_RATE_LIMITED`           | Ralentissez, réduisez le nombre de requêtes simultanées et réessayez après un court délai.                                                                                                                                                                                                                                                                        |
| `ERROR_REASON_MODEL_UNAVAILABLE`      | Si l’erreur est `invalid_argument`, le modèle n’est pas autorisé : choisissez-en un autre. Si elle est `failed_precondition`, demandez à l’opérateur d’enregistrer les tarifs du modèle.                                                                                                                                                                          |
| `ERROR_REASON_UNSUPPORTED_SCHEMA`     | Supprimez les mots-clés qui ne font pas partie du [sous-ensemble pris en charge](/fr/services/delitools/api-reference). La racine doit être un schéma d’objet.                                                                                                                                                                                                    |
| `ERROR_REASON_PROVIDER_FAILED`        | Avec le code Connect `unavailable`, attendez et réessayez. Avec `internal`, le fournisseur a rejeté la requête : ne la réessayez pas sans modification, vérifiez-la et contactez l’opérateur en lui communiquant l’identifiant de la requête.                                                                                                                     |
| `ERROR_REASON_INVALID_OUTPUT`         | Réessayez une fois. Simplifiez le schéma ou les données d’entrée si le problème se reproduit. La tentative est facturée.                                                                                                                                                                                                                                          |
| `ERROR_REASON_EXTRACTION_FAILED`      | Le texte ne contient pas les informations requises. Fournissez les détails manquants ou rendez la propriété facultative dans votre schéma. La tentative est facturée.                                                                                                                                                                                             |
| `ERROR_REASON_TIMEOUT`                | Envoyez des requêtes plus petites. Réessayez plus tard.                                                                                                                                                                                                                                                                                                           |
| `ERROR_REASON_CANCELED`               | Votre client a fermé la connexion. Vérifiez les délais d’expiration ou les arrêts du client.                                                                                                                                                                                                                                                                      |
| `ERROR_REASON_DEPENDENCY_UNAVAILABLE` | Réessayez plus tard. DeliTools refuse les traitements payants lorsqu’il ne peut pas vérifier l’autorisation.                                                                                                                                                                                                                                                      |

## Problèmes courants

- **Une clé fonctionne pour une requête, puis échoue pour la suivante.** Une clé expirée, révoquée ou appartenant à un utilisateur qui a perdu ses autorisations cesse de fonctionner immédiatement. Vérifiez-la avec `ListApiKeys`.
- **Une simple erreur `resource_exhausted` sans motif.** Le corps de votre requête dépasse la limite globale de taille définie par l’opérateur. Envoyez moins de données.
- **Un résultat semble incorrect.** Les modèles peuvent commettre des erreurs, et un résultat conforme à votre schéma n’est pas nécessairement correct. Clarifiez les instructions dans les champs `description` de votre schéma et vérifiez les valeurs importantes.
- **Frais inattendus.** Les tentatives échouées dont l’utilisation est connue et les requêtes répétées sont facturées. Consultez la [facturation](/fr/services/delitools/billing).
- **Aucune utilisation visible pour le moment.** Les données d’utilisation parviennent à Delcore peu après l’appel. Vérifiez à nouveau plus tard.

## Demander de l’aide

Indiquez l’identifiant de la requête figurant dans le corps de la réponse ou dans l’en-tête `X-Delitools-Request-Id`, le nom de la procédure, l’heure et le motif de l’erreur. N’envoyez pas votre clé API, votre jeton de connexion ni les textes que vous avez soumis.
