# DeliTools 计费

DeliTools 根据您的请求使用的 AI token 向您的租户计费。Delcore 负责按用量计价，并管理您的余额、额度和发票。本页说明用量如何转化为费用。

## 计量内容

- DeliTools 读取 AI 提供商为每次尝试报告的**输入 token** 和**输出 token** 总数，并直接使用这些报告的总数。
- 报告的总数已包含所有缓存或推理 token。DeliTools 不会重复计算这些部分，不提供单独的缓存折扣，也不对推理收取附加费用。
- DeliTools 将输入和输出用量分别报告给 Delcore，Delcore 按各自的价格计费。

## 价格

- 服务运营方在 Delcore 中为每个模型设置各 token 方向（输入和输出）的价格。不同模型的价格可能不同。
- 翻译和提取使用相同的价格。提取始终使用 `openai/gpt-6-luna`，因此按该模型的输入和输出价格计费。
- 如果某个模型未同时登记输入和输出价格，则无法运行。请求将失败并返回 `ERROR_REASON_MODEL_UNAVAILABLE`，且不会改用其他模型。
- 价格变更适用于变更后开始的执行。已经开始的执行仍按开始时的价格计费用量。
- 您的套餐决定所含用量、余额，以及余额用尽后是否可以继续使用。请在 Delcore 中查看您的套餐和发票。

## 收费范围

- **每次用量已知的尝试都会收费。** 这包括结果无效、提取失败、在您取消之前答案已返回，或结果始终未送达您的尝试。
- **重试视为单独的尝试。** 如果 DeliTools 因提供商的暂时性故障而重试，且失败的尝试报告了用量，则两次尝试都会收费。未报告用量的失败尝试不收费。
- **用量未知时不收费。** 如果提供商未报告可用的 token 总数，DeliTools 不会估算费用，也不会在之后查询该用量。
- **中止的调用不收费。** 如果您取消请求或执行超时时，提供商调用仍在运行，则不会收到用量报告，也不会收取任何费用，即使提供商已经开始处理。这是一个已知限制：DeliTools 不会在事后查询这部分用量。
- **必须记录用量。** DeliTools 在返回响应之前，会存储每次尝试的用量。如果无法存储，请求将失败并返回 `ERROR_REASON_DEPENDENCY_UNAVAILABLE`，您也不会收到任何结果。
- **被拒绝的请求不收费。** 未通过验证、身份认证或授权的请求，或触发限制或使用不受支持的 schema 的请求，都不会发送到 AI 提供商。
- **每次调用都是新的调用。** DeliTools 不支持幂等键，也不会重放结果。如果您再次发送相同请求，该请求会再次运行并再次收费。

## 费用何时显示

DeliTools 在向您返回响应之前，会保存每次尝试的用量，然后将其报告给 Delcore。用量上报独立于您的请求，因此费用可能会在调用结束后不久显示在 Delcore 中。如果 Delcore 不可用，DeliTools 会使用相同的标识符持续重试，因此重试不会产生重复费用。

DeliTools 无法送达的用量记录会在创建 30 天后删除，重试不会延长该期限。在此期间始终未送达的用量不会收费。DeliTools 不会对其进行估算。

您可以在 Delcore 中查看用量和费用。DeliTools 的响应不包含这些信息。

## 余额检查与超额使用

Delcore 会在每次请求之前以及每次重试之前检查您的授权和计费状态。它不会为调用预留资金或 token。只有调用完成后，费用才会确定。因此，同时运行的多个请求可能会超出您的剩余余额或套餐所含用量。当余额或某项限额耗尽时，Delcore 会阻止后续请求，并返回 `ERROR_REASON_BILLING_BLOCKED`。

如果无法连接到 Delcore，DeliTools 会拒绝新的付费请求，而不是继续执行。

## 被阻止的请求

`ERROR_REASON_BILLING_BLOCKED` 表示 Delcore 已阻止您的租户使用付费功能。常见原因包括余额耗尽、续费失败或付费周期已到期、存在尚未解决的争议、运营方实施了封禁，或租户正在被删除。请在 Delcore 中解决相应问题，例如充值余额或续订订阅。在付费使用被阻止期间，租户管理和付款恢复功能仍然可用。
