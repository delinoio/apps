# DeliTools 计费

DeliTools 根据您的请求所使用的 AI token 向您的租户计费。Delcore 对用量计价，并管理您的余额、抵扣额度和发票。本页说明用量如何转化为费用。

## 计量内容

- DeliTools 读取 AI 提供商针对每次尝试报告的**输入 token** 和**输出 token** 总数，并直接使用所报告的总数。
- 报告的总数已包含所有缓存 token 或推理 token。DeliTools 不会重复添加这些部分，不提供单独的缓存折扣，也不对推理收取附加费。
- DeliTools 将输入和输出用量分别报告给 Delcore，Delcore 按各自的价格计费。

## 价格

- 服务运营方在 Delcore 中为每个模型的各 token 方向（输入和输出）设置价格。不同模型的价格可能不同。
- 翻译和提取使用相同的价格。提取始终使用 `openai/gpt-6-luna`，因此其费用按该模型的输入和输出价格计算。
- 未同时登记输入和输出价格的模型无法运行。请求会失败并返回 `ERROR_REASON_MODEL_UNAVAILABLE`，且不会改用其他模型。
- 价格变更适用于变更后开始的执行。已经开始的用量仍按开始时的价格计费。
- 您的套餐决定了内含用量、余额，以及余额用尽后能否继续使用。请在 Delcore 中查看您的套餐和发票。

## 计费范围

- **每次用量已知的尝试都会计费。** 这包括结果无效、提取失败、回答在您取消前已到达，或结果始终未送达您的尝试。
- **重试属于单独的尝试。** 提供商的暂时性故障（网络错误或 HTTP 5xx 或 429 响应）不会返回用量，因此 DeliTools 会重试，且不会对失败的那次尝试收费。提供商返回完整且用量已知的响应后，尝试循环即告结束，并会计费，即使输出无效也是如此，因为 DeliTools 从不会为修复无效输出而重试。不包含用量的响应不收费。
- **未知用量不计费。** 如果提供商未报告可用的 token 总数，DeliTools 不会估算费用，也不会在之后查询该用量。
- **中止的调用不计费。** 如果您取消时或执行超时时，提供商调用仍在运行，则不会收到用量报告，也不会产生费用，即使提供商已经开始工作。这是一项已知限制：DeliTools 不会在事后查询这部分用量。
- **必须记录用量。** DeliTools 会在响应前存储每次尝试的用量。如果无法存储，请求会失败并返回 `ERROR_REASON_DEPENDENCY_UNAVAILABLE`，您将不会收到结果。
- **被拒绝的请求不计费。** 未通过验证、身份认证或授权，或者触及限制或使用了不受支持的 schema 的请求，不会发送至 AI 提供商。
- **每次调用都是全新的。** DeliTools 不提供幂等键，也不重放结果。如果您再次发送相同的请求，它会再次运行并再次计费。

## 费用何时显示

DeliTools 会在响应您之前保存每次尝试的用量，然后将其报告给 Delcore。用量报告与您的请求相互独立，因此费用可能会在调用结束后不久显示在 Delcore 中。如果 Delcore 不可用，DeliTools 会使用相同的标识符持续重试，因此重试不会产生重复费用。

DeliTools 无法送达的用量记录会在创建 30 天后删除，重试不会延长这一期限。在此期间始终未送达的用量不计费。DeliTools 不会对此进行估算。

您可以在 Delcore 中查看用量和费用。DeliTools 的响应不包含这些信息。

## 余额检查与超支

Delcore 会在每次请求前以及每次重试前检查您的授权和计费状态。它不会为调用预留资金或 token。只有调用结束后才能确定费用。因此，同时运行的多个请求可能会消耗超出您剩余余额或内含用量的额度。当余额用尽或达到限制时，Delcore 会阻止后续请求，并返回 `ERROR_REASON_BILLING_BLOCKED`。

如果无法连接 Delcore，DeliTools 会拒绝新的付费请求，而不会运行它们。

## 被阻止的请求

`ERROR_REASON_BILLING_BLOCKED` 表示 Delcore 阻止了您租户的付费使用。常见原因包括余额用尽、续订失败或付费期限已过、有尚未解决的争议、被运营方阻止，或租户正在删除中。请在 Delcore 中解决相应问题。例如，为余额充值或续订订阅。在付费使用被阻止期间，租户管理和付款恢复功能仍然可用。
