# Delcore

Delcore 为 Delino 服务提供共享租户、访问控制和计费功能。官方 API 服务器为 `https://delcore.api.delino.io`。本页面向服务开发者，介绍 API 密钥验证、用量定价、记录过期和租户状态检查。

## 检查租户状态

已注册的服务可以向 Delcore 查询租户是处于活跃、已封禁还是已删除状态。当你的服务为租户存储数据，但并非每个请求都有对应的 Delino 用户时，例如通过项目 API 密钥发起调用时，请使用此检查。

调用 `delcore.v1.DelcoreService/GetTenantStates`，传入 1 至 100 个租户 ID。每个 ID 必须是小写的 UUID 版本 7。使用你的服务的 Logto 机器对机器应用的访问令牌进行身份验证。该服务必须已在 Delcore 注册，并具有 `authorize` 作用域。用户令牌、未注册的服务以及不具备此作用域的服务均无法读取租户状态。

响应会按你发送的顺序返回每个请求的租户 ID，并附带一个状态：

| 状态                    | 含义                                       |
| ----------------------- | ------------------------------------------ |
| `TENANT_STATE_ACTIVE`   | 租户存在，且未被封禁，也未处于删除过程中。 |
| `TENANT_STATE_BLOCKED`  | 平台操作员已封禁该租户。                   |
| `TENANT_STATE_DELETING` | 正在等待删除。                             |
| `TENANT_STATE_DELETED`  | 删除已最终完成。                           |
| `TENANT_STATE_UNKNOWN`  | Delcore 中不存在具有此 ID 的租户。         |

当多个条件同时适用时，`DELETED` 优先于 `DELETING`，`DELETING` 优先于 `BLOCKED`，`BLOCKED` 优先于 `ACTIVE`。

状态不取决于计费情况。订阅过期、续订失败、争议或余额不足都不会使租户变为 `BLOCKED`。要判断用户是否可以执行付费任务，请改用 `Authorize`。此检查仅读取数据。它不会更改租户、授权付费使用或联系支付服务提供商，也不会返回租户名称、用户详情或计费信息。

## 处理结果和失败

- 仅当状态为 `TENANT_STATE_ACTIVE`，或你自己的已记录规则允许所有者或管理员访问被封禁或正在删除的租户时，才允许访问。
- 对于 `TENANT_STATE_UNKNOWN`、请求错误、超时以及 Delcore 不可用的情况，均应拒绝访问。在这些情况下不要删除数据。
- 对于因租户删除而触发的清理，只有在明确收到 `TENANT_STATE_DELETED` 后，才能自动删除你保留的租户数据。`BLOCKED` 和 `DELETING` 都不允许进行此类清理。固定的记录过期规则独立于租户状态生效。
- ID 无效、请求为空或 ID 超过 100 个时，会返回参数无效错误。凭据缺失、过期或无效时，会返回未通过身份验证错误。不被允许读取租户状态的调用方会收到权限被拒绝错误。其他失败会返回带有关联 ID 的错误；寻求支持时，请提供此 ID，可在错误详情和 `X-Delcore-Correlation-Id` 标头中找到它。
- 请求失败后，请稍后重试。请求失败绝不意味着租户处于活跃或已删除状态。

## 用量价格和记录过期

用量单价以首次开始执行时的价格为准，适用于所有客户，包括现有订阅者。在 `IngestEvent` 中通过 `occurred_at` 报告该开始时间，并在执行重试和用量对账过程中保持不变。价格变更适用于之后开始的执行；延迟送达和更正仍保持原始价格归属。周期性付款价格、所选功能和包含用量的授予额度仍遵循其订阅条款。

请求去重有效期为自记录首次创建起 30 天。重试不会延长此期限。过期后，同一请求键可以发起新操作，但须遵守当前权限以及独立的支付或事件身份检查。已接受的用量事件会保留其持久标识，以防止重复记账。

调用方服务必须在用量投递和对账记录首次创建 30 天后将其删除，即使执行情况或用量仍然未知，或报告尚未送达 Delcore，也不例外。在过期之前，应持续重试投递并查询未知用量；过期后则放弃待处理的收费。不要通过估算用量来计费。这可能导致可计费用量永久丢失，而过期的执行去重键可能允许再次执行并收费。平台审计记录和运行日志也会在创建 30 天后过期。这些限制不会删除 Delcore 已接受的会计分录，也不会改变 API 密钥的有效性。

## 验证 API 密钥

Delcore 可为任何已注册服务签发可重复使用的个人 API 密钥和租户服务 API 密钥。用户以及租户所有者和管理员可使用 Delino 登录令牌创建这些密钥；面向用户的流程请参阅 [DeliTools API 密钥](/zh-Hans/services/delitools/api-keys)。密钥以 `dlk_` 开头，授予所选服务的所选能力，并归属于一个租户。

已注册服务通过 `delcore.v1.DelcoreService/AuthorizeApiKey` 验证从调用方收到的密钥。使用你的服务的 Logto 机器对机器访问令牌进行身份验证。该服务必须已注册，并具有 `authorize` 作用域。

- 发送完整的 `secret`、正在使用的 `capability`，并在执行付费任务时发送 `paid`。你也可以像在 `Authorize` 中一样发送 `feature_key` 和 `group_values`。
- Delcore 仅评估明确指定调用服务的授权，因此你的服务绝不可能授权其他服务的能力。
- 格式错误、未知、已撤销或已过期的密钥，或属于已删除租户的密钥，都会返回未通过身份验证错误，且不包含密钥详情。当你自己的服务令牌被拒绝时，Delcore 也会以这种方式响应，因此，如果所有有效密钥都验证失败，请检查你的服务凭据。应将其视为无效凭据。
- 对于有效密钥，响应包含 `allowed`、`reasons` 和可选的 `feature`，以及 `keyId`、`tenantId`、`ownerKind` 和 `userId`。不具备该能力的密钥会返回 `allowed: false`，原因为 `BLOCK_REASON_PERMISSION`。
- 个人密钥还要求其用户当前在该租户中拥有对应能力的权限。租户密钥不依赖创建它的用户。两者都要求租户处于活跃状态，并在设置 `paid` 时接受与 `Authorize` 相同的计费检查。
- 如果调用方提供了租户，请将其与返回的 `tenantId` 进行比较；若不匹配，则拒绝请求。
- 检查每一个请求。不要缓存结果。对于错误、超时以及 Delcore 不可用的情况，应拒绝新的付费任务访问。授权结果不会预留任何资源。
