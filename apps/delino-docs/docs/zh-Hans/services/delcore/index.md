# Delcore

Delcore 为 Delino 服务提供共享租户、访问控制和计费功能。官方 API 服务器为 `https://delcore.api.delino.io`。本页面向服务开发者，介绍用量定价、记录过期和租户状态检查。

## 检查租户状态

已注册的服务可以向 Delcore 查询租户是处于活跃、已封禁还是已删除状态。如果你的服务为租户存储数据，但并非每个请求都有对应的 Delino 用户，例如使用项目 API 密钥发起调用时，请使用此检查。

调用 `delcore.v1.DelcoreService/GetTenantStates`，传入 1 到 100 个租户 ID。每个 ID 都必须是小写的 UUID 版本 7。使用你的服务的 Logto 机器对机器应用的访问令牌进行身份验证。该服务必须已在 Delcore 注册，并具有 `authorize` 作用域。用户令牌、未注册的服务以及不具备此作用域的服务均无法读取租户状态。

响应会按你发送的顺序返回每个请求的租户 ID，并附带一个状态：

| 状态                    | 含义                                       |
| ----------------------- | ------------------------------------------ |
| `TENANT_STATE_ACTIVE`   | 租户存在，且未被封禁，也未处于删除过程中。 |
| `TENANT_STATE_BLOCKED`  | 平台运营人员已封禁该租户。                 |
| `TENANT_STATE_DELETING` | 正在等待删除。                             |
| `TENANT_STATE_DELETED`  | 删除已最终完成。                           |
| `TENANT_STATE_UNKNOWN`  | Delcore 中没有此 ID 对应的租户。           |

当多个条件同时适用时，`DELETED` 优先于 `DELETING`，`DELETING` 优先于 `BLOCKED`，而 `BLOCKED` 优先于 `ACTIVE`。

状态不取决于计费情况。订阅过期、续费失败、争议或余额不足都不会使租户变为 `BLOCKED`。要判断用户是否可以执行付费任务，请改用 `Authorize`。此检查仅读取数据。它不会更改租户、授权付费使用或联系支付提供商，也不会返回租户名称、用户详细信息或计费信息。

## 处理结果和失败

- 仅对 `TENANT_STATE_ACTIVE` 允许访问，除非你自己的书面规则允许所有者或管理员访问已封禁或正在删除的租户。
- 将 `TENANT_STATE_UNKNOWN`、请求错误、超时和 Delcore 不可用视为不允许访问。在这些情况下，不要删除数据。
- 对于因租户删除而进行的清理，只有在收到明确的 `TENANT_STATE_DELETED` 后，才能自动删除你保留的租户数据。`BLOCKED` 和 `DELETING` 绝不允许进行此类清理。固定的记录过期规则独立于租户状态适用。
- 无效的 ID、空请求或超过 100 个 ID 会返回参数无效错误。凭据缺失、过期或无效会返回未通过身份验证错误。无权读取租户状态的调用方会收到权限被拒绝错误。其他失败会返回带有关联 ID 的错误；寻求支持时，请提供此 ID，可在错误详情和 `X-Delcore-Correlation-Id` 标头中找到它。
- 稍后重试失败的请求。请求失败绝不意味着租户处于活跃或已删除状态。

## 用量价格和记录过期

用量单价在首次执行开始时适用于所有客户，包括现有订阅者。在 `IngestEvent` 中将该开始时间报告为 `occurred_at`，并在执行重试和用量核对过程中保持不变。价格变更适用于之后开始的执行；延迟送达和更正仍保留原始价格归属。周期性付款价格、所选功能和内含用量额度仍遵循其订阅条款。

请求去重有效期为自记录首次创建起 30 天。重试不会延长此期限。过期后，同一请求键可以发起新操作，但须受当前权限以及独立的支付或事件身份检查约束。已接受的用量事件会保留其持久标识，以防止产生重复的账务影响。

使用这些功能的服务必须在用量投递和核对记录首次创建 30 天后删除这些记录，即使执行情况或用量仍然未知，或者报告尚未送达 Delcore。持续重试投递和未知用量查询，直到该期限届满，然后放弃待处理的收费。不要估算用量来计费。这可能导致可计费用量永久丢失，而且已过期的执行去重键可能允许新的执行和收费。平台审计记录和运维日志也会在创建 30 天后过期。这些限制不会删除 Delcore 已接受的账务条目，也不会改变 API 密钥的有效性。
