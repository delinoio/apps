# Prepare Lane artifacts

Run root `pnpm install`, then `pnpm --filter @delinoio/lane test`, `pnpm --filter @delinoio/lane build`, and `pnpm --filter @delinoio/lane smoke`. Use the CI-selected Rust and root-selected Node versions. Packaging requires committed CLI, Cargo workspace/lockfile, canonical SQLite schemas, protocol, launcher and license inputs. It refuses a dirty source or a source revision change during the build.

`node packages/lane/scripts/build.mjs --source-root <absolute-checkout>` can read a separately owned committed CLI checkout without modifying it. The manifest records CLI source and launcher revisions separately. This is a packaging input, not a protocol dependency pin or an alternative workspace integration model. Final integrated acceptance should run the normal build from the integrated revision.

The build runs `cargo build --locked --release -p lane --target <triple>` for darwin/linux/windows on amd64/arm64. Install `protoc`, the Rust standard library target and matching linker/native SDK before building each target; Rust does not provide those cross-platform native toolchains. Cargo and npm package versions must match. For host validation, select a subset explicitly, for example `pnpm --filter @delinoio/lane build --platform darwin-arm64`. Repeat `--platform` for multiple targets. The default builds all six; a subset is a validation artifact, not a complete release package. It collects dependency crates for the selected targets, includes their license/notice texts plus Rust toolchain notices, and includes root LICENSE/NOTICE. Missing dependency notices stop packaging. Review the generated module inventory against the executable dependency graph when dependencies change.

`dist/artifacts/lane-<os>-<arch>/lane[.exe]` provides the matching helper to native packaging. That directory also contains its version/platform/SHA-256 manifest and licenses. Native packaging must copy the executable to the host executable directory’s `helpers/lane` on macOS or `helpers/lane.exe` on Windows. Never place it beside the `Lane`/`Lane.exe` GUI executable: case-insensitive filesystems can overwrite the host. Native packaging checks must assert distinct resolved host/helper paths, verify the helper version against this artifact, and launch the actual GUI host separately. npm smoke checks contain no GUI executable and cannot establish that native gate. `dist/lane-<os>-<arch>-<version>.tar.gz` is the direct archive, and `dist/delinoio-lane-<version>.tgz` is the npm candidate. `dist/SHA256SUMS` covers all archives. No publish or release command runs.

`test` uses explicitly synthetic executables and an offline disposable npm install. `smoke` installs the real packed package offline, checks every artifact/archive and its notices, then runs the host executable and launcher with `--version`, `--help`, and MCP initialization/tool discovery. Discovery does not open or mutate local user data. Cross-builds and archive checks do not establish execution on another OS/CPU, native GUI acceptance, provider delivery, or publication. Record those limits and exact source revisions with validation.

Remove generated `dist` directories after retaining review evidence outside the worktree. Do not commit executables or archives.
